# 28단계 보고 — 귀참·일섬 이펙트 수정 (연참 유지)

순수 연출 작업이다. **밸런스·세이브는 건드리지 않았다.** 총 데미지와 타격 분배도 그대로다.

## 0. 원인 — 지적이 정확했다

27단계 이펙트는 `Slash_White.png`(128px 스프라이트) 한 장을 화면 크기까지 키워 쓴 것이었다.
귀참은 3.4배, 일섬은 회전까지 얹었다. 결과가 "거대한 주황 덩어리"였던 이유가 그것이다 —
**32 PPU 픽셀 아트를 세 배로 늘리면 픽셀 하나가 화면에서 12px 네모가 된다.**

28단계는 스프라이트를 쓰지 않는다. **절차적 메시 트레일**로 바꿨다.
정점 색을 직접 넣으므로 화면 픽셀 단위로 매끄럽고, 크기를 키워도 커지는 것은 도형이지
텍스처가 아니다.

`SkillSlash.cs`와 `SkillSlash.prefab`은 지웠다. `Slash_White.png`는 다시 미사용이다.

## [F-1] 귀참 — 화면 광역

### 궤적: 얕고 넓은 호

![귀참 궤적](../Assets/Screenshots/step28_oni_arc.png)

값을 눈대중으로 잡지 않고 **전투 띠에서 역산**했다. 카메라는 x −4.01~4.01,
사무라이 스프라이트는 y −0.63~2.37, 요괴는 y −0.16~0.71(지상) / 0.19~1.03(도깨비불)에 선다.
호가 꼭대기 y=1.4, 양 끝 y=−0.6, 가로 ±3.7을 지나도록 풀면

```
R(1 − sin θ) = 2.0 ,  R·cos θ = 3.7   →   θ = 33°, R = 4.42
원 중심 y = 1.4 − R = −3.02
```

가로 7.4u = **카메라 폭 8.03u의 92%**. 실측한 호의 통과점:

| t | 0.00 | 0.25 | 0.50 | 0.75 | 1.00 |
|---|---|---|---|---|---|
| 좌표 | (3.71, −0.61) | (2.11, 0.86) | (0.00, 1.40) | (−2.11, 0.86) | (−3.71, −0.61) |

**두 번 틀렸다가 고쳤다.** 처음에는 사무라이 가슴을 중심으로 반지름 3.4, 200~365°를
썼는데 그 각도 범위가 통째로 중심의 아래쪽이라 호가 지면 밑으로 빠졌다 — 스크린샷에
화면 오른쪽 아래 구석만 잘려 보였다. 두 번째로 중심을 −2.05까지만 내렸더니 이번에는
호가 요괴들 **위로** 지나갔다. 세 번째가 위 값이다.

### 색: 어두운 코어 + 밝은 윤곽

먹빛 흑적 `#24080E` 알파 0.82, 윤곽 `#FFD8C8`(가산).

여기서 **정점 구조를 고쳐야 했다.** 처음 단면은 다섯 정점이었다 —
`바깥(a=0) / 테두리 / 중심 / 테두리 / 바깥`. 그런데 코어 띠가 테두리 정점에서 시작하므로
그 띠의 색이 **밝은 테두리색에서 어두운 코어색으로 이어지는 그라데이션**이 된다. 폭의
대부분이 밝은 쪽에 걸려, 화면에는 어두운 참격이 아니라 **크림색 초승달 한가운데에 어두운
선 하나**가 떴다. 테두리 비율을 0.42 → 0.78로 옮겨도 그대로였다 — 원인이 비율이 아니라
정점 공유였기 때문이다.

그래서 테두리 자리에 **정점 두 개를 겹쳐 둔다.** 하나는 테두리색, 하나는 코어색이다.
자리가 같으므로 사이 사각형은 없고 색만 뚝 끊긴다. 그 끊김이 곧 어두운 칼몸 + 밝은 윤곽선이다.
단면은 일곱 정점이 됐다.

윤곽색을 금빛 `#FFC878`로 뒀을 때는 코어가 제자리를 잡은 뒤에도 전체가 주황으로 읽혀,
흰빛에 가까운 `#FFD8C8`로 바꿨다.

**알파 0.82는 의도한 값이다.** 1.0이면 호가 지나는 동안 사무라이와 요괴가 통째로 검게
지워진다. 위 스크린샷에서 호 뒤로 요괴와 데미지 숫자가 계속 보이는 것이 그 값이다.

### 화면 연출: 흰 풀스크린 → 엣지 번쩍 + 닫히는 비네트

![귀참 화면 연출](../Assets/Screenshots/step28_oni_screen.png)

가운데는 건드리지 않는다. 실측한 두 겹의 알파:

```
t=0.000  edge=0.60  vignette=0.00      번쩍이 곧바로 최대
t=0.017  edge=0.70* vignette=0.30      비네트가 닫히기 시작
t=0.049  edge=0.43  vignette=0.87      0.05초에 최대까지 닫힘
t=0.099  edge=0.01  vignette=0.85      번쩍 종료
t=0.334  edge=0.00  vignette=0.03      0.34초에 걸쳐 천천히 열림
                                       (*edgePeak 0.85 시절 측정)
```

닫힘 0.05초 / 열림 0.29초. **닫힘은 사건이고 열림은 여운이라** 같은 속도로 여닫으면
숨 쉬는 것처럼 보인다.

**여기서 두 가지가 틀려 있었고 둘 다 픽셀을 재서 찾았다.**

1. **엣지 번쩍이 아예 합성되지 않았다.** 비네트 텍스처를 `Color(0,0,0,a)` — 즉 **검게**
   구워 뒀는데, 같은 스프라이트를 살굿빛 `#FF8A6A`로 틴트한 엣지 번쩍은 Image의 색이
   스프라이트에 **곱해지므로** 검정 × 주황 = 검정이었다. 화면 가장자리 픽셀을 재 보니
   밝아지기는커녕 더 어두워졌고(t=0.017에서 하늘 0.49 → 0.29), 붉은 쪽으로 치우침도 없었다
   (r/b 비가 계속 0.82). 텍스처를 **흰색**으로 다시 구워 고쳤다.

2. **고치고 나니 이번엔 너무 넓었다.** 알파 램프가 r=0.45에서 시작해 r=1.05에서 최대라,
   투명한 코어가 작은 타원뿐이고 나머지 화면 전체가 살굿빛으로 덮였다 — **걷어내려던 흰
   풀스크린을 색만 바꿔 다시 만든 셈이다.** 램프를 0.80~1.35로 조이고 `edgePeak`을
   0.85 → 0.6으로 낮췄다. 이제 각 변의 한가운데(r=1.0)가 0.24, 네 귀퉁이(r=1.41)가 1.0이다.

무게는 화면을 가리는 것이 아니라 **히트스톱 3.0배 / 셰이크 2.8배**가 낸다.

## [F-2] 일섬 — 돌진 관통

![일섬 스트릭](../Assets/Screenshots/step28_flash_streak.png)

곡선 크레센트를 제거하고 **수평 스트릭**으로 바꿨다. 길이 4.6u(관통 사거리와 같다),
폭 0.5u, 기울기 −3°, 앞이 두껍고 꼬리가 가늘다.

높이도 실측이다 — 지상 요괴가 y −0.16~0.71, 도깨비불이 0.19~1.03이므로 **y=0.45를
지나면 둘 다 꿴다**. 사무라이 스프라이트 중심 0.87 기준으로 −0.42.

색은 심 `#FF3A20`, 번짐 `#FFB090`(가산). **심을 붉게 두는 것이 요점이다.** 처음에는
"스피드 라인은 밝아야 한다"고 흰 심 + 붉은 테두리로 뒀는데, 화면에는 그냥 흰 선이 나왔다 —
심이 폭의 74%인데 스트릭 자체가 얇아(반폭 0.25u) 붉은 테두리가 0.065u까지 줄어 사라졌다.
**얇은 것에 테두리로 색을 입힐 수는 없다.**

### DASH 잔상

3장. 실측 위치와 알파:

```
x = −0.73 (a 0.34)  −0.25 (a 0.58)  0.22 (a 0.79)   스프라이트 DASH_0 / DASH_0 / DASH_1
```

**여기가 이번 단계에서 가장 크게 틀렸던 곳이다.** 잔상을 시전 순간에 세 장 한꺼번에
뿌리고 있었는데, 그 시점의 `samuraiRenderer.sprite`는 아직 DASH 클립이 아니라 **직전 평타
프레임**이었다. 화면에 나온 것은 돌진하는 사무라이가 아니라 **평타의 흰 칼궤적이 허공에
한 장 떠 있는 그림**이었고, 스크린샷에서 흰 덩어리로 보이던 것이 그것이다.

타격과 같은 방식으로 바꿨다 — 잔상마다 시각이 걸려 있고 그 시각을 지날 때 하나가 나간다.
시각이 고정이므로 개수는 여전히 프레임률과 무관하고, 그리는 그림은 그 순간의 DASH 프레임이 된다.

자리는 **시간이 아니라 거리를 균등하게 나눈다.** 시간을 나누면 돌진 곡선이
ease-out(처음이 가장 빠르다)이라 잔상이 도착 지점 쪽에 뭉친다 — 실측으로 세 장이
0.83 / 1.43 / 1.78u에 놓여 뒤 두 장이 0.36u 안에 붙었다. 거리를 나누고 시각을 곡선에서
역산(`x = 1 − √(1−f)`)하면 0.475 / 0.95 / 1.425로 고르게 서고, **잔상이 본체보다 앞서
나타나지도 않는다.**

돌진 거리는 1.25 → 1.9u로 늘렸다. 1.25에서는 잔상 세 장이 화면 폭의 15% 안에 겹쳐
한 덩어리로 보였다. **X 앵커 복귀는 그대로다**(`lungeBack`이 0을 돌려준다).
관통 사거리 4.6 × 세로 2.6도 그대로다.

잔상 색 알파는 0.5 → 0.8. 0.5에서는 가장 옅은 장이 0.17까지 내려가 화면에 안 보였다.

## [F-3] 연참 — 그대로

![연참 그대로](../Assets/Screenshots/step28_chain_intact.png)

씬에 박힌 값을 되읽어 확인했다:

```
id=skill_chain  clip=20f @40fps  hits=[4,10,16]  usesArc=False
trailLen=0  trailWidth=0  ghosts=0  lunge=0
hitStop=1.4  shake=1.1  perHitShake=0.55  numberSize=1  flash=False
```

27단계 값과 **한 자도 다르지 않다.** 구조적으로도 닿지 않는다 —
트레일 변경은 `usesArc=False`라 타지 않고, 잔상 타이밍 변경은 `afterimageCount=0`이라
양쪽 경로 모두 no-op이며, 비네트 텍스처 변경은 `flash=False`라 무관하다.

## 못 한 것 / 남는 것

- **GIF은 만들지 못했다.** 프레임 스트립으로 대신했다. 에디터에서 캡처를 프레임마다
  거는 방식이라 균일한 간격의 연속 프레임을 뽑기 어려웠고(요청한 12장이 같은 렌더
  프레임에 몰려 마지막 한 장만 남는 문제를 `Time.frameCount` 게이트로 막아야 했다),
  타임스케일을 낮춘 상태의 프레임을 이어 붙이면 실제 속도와 다른 GIF이 된다.
  실제 속도의 GIF이 필요하면 별도로 잡겠다.
- 귀참 호의 양 끝이 지면 아래 UI 띠에 아주 살짝 걸친다(끝은 뾰족해서 얇다). 눈에 거슬리면
  폭이나 끝 각도를 줄이면 된다.
