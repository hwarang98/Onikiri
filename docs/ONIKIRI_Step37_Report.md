## P1-1 상단바 — 빡빡함의 원인은 처치 카운터였다

원래 1행은 골드·보석·"지역 4 · 7/10  처치 3/10"이 1080px을 다투고 있었다
(스테이지 상자와 보석 라벨이 이미 겹친 채 우측정렬로만 버티는 구조).
재배치의 핵심 수는 **처치 카운터를 상단바에서 빼서 보스 도전 버튼 자리로
옮긴 것**이다(BossQuota) — 카운터가 차면 같은 자리가 도전 버튼으로 바뀌므로
"채우면 무슨 일이 생기는가"가 한 자리에서 이어지고, 상단바에는 버튼 두 개
세울 여유가 생겼다.

최종 배치 (1080 기준, 밴드 192px 두 줄):

```
1행  [금화 6.0T] [보석 0]        [ 지역 2 · 2/10 ]   <- 재선택 버튼 (490px)
2행  [레벨 74] [★ ====EXP====] [레벨업] [설정]
      ^스탯 창 버튼                        ^설정 버튼
```

- 폭은 전부 실측이다. 32단계 교훈(어림 금지)을 검사기로 확장 —
  `VerifyExpRowFits`가 2행만 재던 것을 **1행까지** 재도록 넓혔다: 골드
  "999.9aa"(실측 183→상자 188), 보석 "99,999"(160→166), 스테이지
  "지역 4 · 10/10  클리어"(449→458), 재화 묶음-스테이지 버튼 간격(상수 유도,
  여유 2px). 이번 작업 중에도 이 검사가 세 번 빌드를 막았다 — 어림으로 잡은
  첫 폭들이 전부 틀렸었다.
- 9:16 / 9:19.5 / 9:21 실기 캡처로 겹침·잘림 없음 확인 (SafeArea + 폭 우선
  스케일 구조는 기존 그대로).
- 순수 레이아웃 — 값·갱신 경로 무변경 (HUDCurrency/HUDGems/LevelHud 그대로,
  HUDStage 문구만 축소).

## P1-2 스탯 창 — 곱셈은 두 곳뿐이다

레벨 버튼(레벨 74 판)을 누르면 열린다. 총 공격력 / 공격 속도(+오의 환산) /
치명타(확률 x배수) / 최대 체력 / 초당 회복 / 골드 획득 / 동료 지원 / 추정
DPS 여덟 줄 + "공격 배수  증폭 x1.19 · 장비 x1.30 · 전직 x1.00" 내역 한 줄.

값의 출처는 전부 기존 경로다: PlayerCombat/PlayerHealth의 프로퍼티는
UpgradeSystem.Apply가 증폭·장비·전직을 **이미 곱해 넣은** 최종값이라, 이
창의 곱셈은 (a) 추정 DPS에 동료 몫 x(1+0.12) — PetCombat이 때리는 식과
동일 — 과 (b) 백분율 표기 변환뿐이다. 실기 검증: 총 공격력 94.3K =
강화값 60.82K x 증폭 1.19 x 장비 1.30 ✓, DPS 500.6K = 94.3K x (1.84+2.40)
x 치명타 1.12 x 동료 1.12 ✓. 갱신은 열려 있는 동안 0.25초 폴링
(PlayerCombat에 Changed 이벤트가 없다 — 컴포넌트 주석에 근거).

## P1-3 스테이지 재선택 — 최전선(maxStageReached) 모델

스테이지 버튼("지역 2 · 2/10")을 누르면 지역 목록이 열린다: 클리어/현재
위치/잠김 표시 + "최전선으로 (N)" 복귀 버튼. **지역 단위**로 이동한다
(스테이지 단위 세부 선택은 골드/초가 최전선 단조 최적이라 실익이 없다 —
되돌아가는 이유는 수치가 아니라 "그 지역"이다).

규칙은 전부 `StageProgress`에 있다:

- **최전선**: `maxStageReached`가 세이브 v12에 생겼다. `SelectStage`는
  1~최전선으로 클램프 — 미클리어 앞지르기는 구조적으로 불가능하고, 보스
  게이트(AdvanceStage)가 유일한 상승 경로라는 규칙이 유지된다.
- **최전선 아래에서는 보스가 잠긴다** (`CanChallenge`에 `IsAtFrontier`
  추가). 클리어한 보스를 다시 잡을 수 있으면 클리어 보너스·보스 경험치가
  반복 수급되고 bossKillCount가 이중으로 오른다. 복귀는 "최전선으로"
  버튼이 맡고, 상단바는 그 상태를 "클리어"로 말한다.
- **재선택은 최전선 st11부터** (`ReselectUnlockStage` = 대장간과 같은 지점,
  지역 1 완주). 온보딩 노이즈 때문만이 아니다 — 아래 밸런스 절 참고.
- 해금 게이트 재기준: LockedTab·UpgradeButton·EquipmentSystem·PetSystem·
  퀘스트 도달 지표·업적 골드 기준이 전부 현재 스테이지 대신 **최전선**을
  읽는다. 재선택으로 st31 아래에 내려간 순간 동료가 화면에서 사라지고
  대장간이 다시 잠기는 사고를 막는다.
- 이동은 파밍 중에만(보스전 도중 배수가 갈리는 것 방지, 테스트 패널과 같은
  가드), 이동 시 필드는 보상 없는 ClearField로 정리.

## P1-4 밸런스 — "최전선이 최적"을 시뮬로 못 박았다

**골드/초: 전 구간 최전선이 단조 최적.** 곡선 구조가 보장한다 — 한 스테이지
내려가면 처치가 1.55배(체력 배수) 빨라지는 대신 골드가 1.72배 깎이고, 처치가
스폰 하한(0.4초)에 닿으면 격차가 더 벌어진다. `StageReselectTests`가 곡선
추종 스탯(시뮬 50스테이지 전체)으로 모든 (최전선, 하위 스테이지) 쌍을 실측
— 통과.

**경험치/초: 역전이 구조적으로 존재해서 규칙으로 닫았다.** 경험치 증가율
(1.16)이 체력 배수(1.55)보다 완만한 것이 "레벨은 골드보다 느리게"의 유일한
장치인데, 그 완만함이 재선택과 만나면 **뒤로 갈수록 경험치/초가 오른다**
(실측: 최전선 2에서 1스테이지 파밍이 +44%, 최전선 11에서 st7이 +6.8%,
보스에 막힌 플레이어일수록 몇 배까지). 곡선을 세우는 것은 밸런스 변경이라
막혔으므로 축을 닫았다: **최전선 아래에서는 잡몹 경험치가 0이다**
(`ExpCurve.MobExp(stage, atFrontier)`, 방치 경험치도 같은 판정). 재선택
화면에 "클리어한 지역은 골드만 - 경험치는 최전선에"로 명시했고, 역전이
지금도 존재함을 확인하는 죽은 버튼 검사(`ExpInversion_StillExists…`)를
남겼다 — 곡선이 바뀌어 역전이 사라지면 이 검사가 깨져 규칙 재검토를 알린다.

**방치 보상: 나갈 때 서 있던 스테이지 기준(기존 동작 유지).** 낮은 데서
나가면 goldPerSecond가 그 낮은 값으로 박히므로 짱박기는 방치에서도
손해다. 실기 확인: st1로 내려간 상태에서 goldPerSec 13.61(최전선 대비
급감), **expPerSec 0.00**. "최전선으로" 버튼이 눈에 띄어야 할 실질적
이유이기도 하다.

**남은 접점(문서화):** 잡몹 **마릿수** 퀘스트 카운터는 최전선 아래에서도
세므로, 저스테이지 원킬 파밍이 마릿수 채우기를 최대 ~2.5배(스폰 하한
2.5마리/초) 가속한다. 일일 퀘스트는 일일 상한으로, 반복 퀘스트는 점증
할당량으로 묶여 있고 보석은 바닥 보장(f2p) 방향의 재화라 밴드 천장을
위협하지 않는다고 판단 — 문제가 되면 카운터도 최전선 게이트에 넣는다.

## 세이브 v12

```
v11 -> v12: data.maxStageReached = max(1, data.stage)
```
v11까지는 스테이지가 내려가는 경로가 없어 "현재 위치 = 최고 도달"이 참 —
아무 상태도 지어내지 않는 마이그레이션이다. 멱등성은 "재선택으로 내려간
v12 상태를 다시 마이그레이션해도 최전선이 안 깎인다"로 검사한다
(`V11_MigrationIsIdempotent`). 미래 버전 거부는 기존 검사 그대로.
테스트 패널 지역 점프(레거시 3인자 SetProgress)도 최전선을 깎지 않는다.

## 덤: 설정 창 (최소)

상단바가 설정 진입점을 요구했고, 진입점만 있고 화면이 없으면 죽은 버튼이라
최소로 세웠다 — 효과음 토글(AudioListener.volume, **PlayerPrefs**에 저장:
음소거는 진행이 아니라 기기 취향이라 세이브 사슬에 태우지 않는다) + 버전
표시. 씬 시작 시 SoundPrefsApplier가 저장값을 적용한다.
