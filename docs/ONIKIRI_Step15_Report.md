# ONIKIRI 15단계 보고서 — 아이콘 행 템플릿 (KURAI Skill Icons)

작업일: 2026-08-06
테스트: EditMode **181/181 통과** (14단계와 동일 — UI 작업이라 테스트가 늘지 않는다)

12-3에서 아이콘 팩이 없어 막혀 있던 **"아이콘 행 템플릿"**을 연다.
14단계는 재질(테두리·눌림)만 입혔고, 이번이 행 자체의 재레이아웃이다.

밸런스와는 독립적이다 — 지금 존재하는 성장 축에 아이콘을 붙인다.

## A. 임포트

| 팩 | 위치 | 들어간 것 |
|---|---|---|
| KURAI RPG Skill Icons v1.7 (구매판) | `Assets/ThirdParty/UI/KuraiSkillIcons/` | **10개 파일, 5KB** |
| Kyrise 16x16 RPG Icons v1.3 | `Assets/ThirdParty/UI/KyriseItemIcons/` | **2개 파일, 44KB** |

### 필요한 것만 넣었다

KURAI는 187개 중 **실제로 쓰는 8개만** 복사했다. Kyrise는 개별 파일이 1054개인데
그대로 넣으면 `.meta`까지 2000개가 되어 모든 AssetDatabase 리프레시가 느려진다.
**스프라이트시트와 readme만** 두고, 장비 시스템이 생길 때 자르기로 했다.

14단계에서 Kenney 스프라이트시트 400칸을 자르지 않은 것과 같은 판단이다 —
쓰지 않을 애셋이 목록을 채우면 필요한 것을 찾는 일이 더 비싸진다.

아이콘을 추가하는 절차는 `KuraiSkillIcons/SOURCE.txt`에 적어뒀다: 원본 폴더에서
`Icon###.png`를 복사하고 `UiIcons.Map`에 한 줄 넣으면 된다.

### 임포트 설정

8개 전부 **PPU 32 / Point / 무압축**으로 들어왔다. `Assets/ThirdParty/`가 기존
`PixelArtImportPostprocessor` 범위 안이라 손댈 것이 없었다.

라이선스: 구매판. 상업적 사용 가능, 크레딧 불필요, 재배포 금지. `ReadMe.txt`를
함께 복사하고 출처를 `SOURCE.txt`에 남겼다.

## 지시와 다르게 판단한 두 가지

### 1. 심볼-only 버전이 팩에 없다

지시: *"프레임 없는 심볼 버전을 쓴다. 팩에 프레임 버전과 심볼-only 버전이 같이
있으면 심볼-only."*

**조건이 성립하지 않는다.** 알파를 재보니 전부 100% 불투명이다.

```
Icon084  16x16  불투명 256/256 (100%)
Icon037  16x16  불투명 256/256 (100%)
Icon114  16x16  불투명 256/256 (100%)
Icon175  16x16  불투명 256/256 (100%)
```

색 배경 타일이 아트에 구워져 있고, 팩에 프레임 없는 변형이 없다.

그래서 배경 포함으로 갔다. 우려하신 "프레임 겹침"은 화면에서 생기지 않았다 —
아이콘이 행 테두리와 경쟁하는 프레임이 아니라 **슬롯**으로 읽힌다. 오히려
KURAI는 **배경색이 곧 색 변형**이라, 지시하신 의미색 매핑(검=빨강, 회오리=파랑,
눈=금색, 심장=초록)을 그 배경이 그대로 실어 나른다.

배경을 프로그램으로 벗겨내는 방법도 있었지만 하지 않았다. 심볼과 배경이 색을
공유하는 구간이 있어 아트가 상한다.

### 2. 증폭 축은 색 변형이 아니라 명도 변형으로 구분했다

지시: *"같은 검·심장 심볼에 '+' 뉘앙스나 다른 변형으로 구분."*

팩에서 다른 색 변형을 뽑아봤다 — 초록 검(`Icon094`), 파랑 심장(`Icon037`).
그런데 **초록은 우리 체계에서 생존색이다.** 초록 검을 공격력 증폭에 쓰면
색(=생존)과 심볼(=화력)이 한 아이콘 안에서 서로를 부정한다. 색을 두 번째 축으로
쓰기로 한 설계가 거기서 깨진다.

대신 **같은 심볼을 반 톤 눌러** "보조"를 밝기로 말하게 했다.

```
Tint           (0.82, 0.80, 0.86)   기본 축
AmplifierTint  (0.58, 0.56, 0.64)   증폭 축
```

증폭이 별개의 스탯이 아니라 **같은 스탯을 다른 재화로 올리는 것**이라는 사실도
같은 심볼이 더 정확하게 말한다. 스크린샷에서 체력 강화(밝은 심장)와 체력
증폭(어두운 심장)이 한 화면에 나란히 있어 구분이 확인된다.

## C. 행 재레이아웃

**좌 아이콘 / 중앙 이름+수치(2줄) / 우 비용.**

| 값 | 크기 | 근거 |
|---|---|---|
| 행 아이콘 | 96px | 16 x **6** |
| 상단 바 아이콘 | 48px | 16 x **3** |
| 행 높이 | 144px | 14단계 그대로 (62 x 2 + 20) |
| 글자 시작 x | 140px | 아이콘 왼쪽 여백 24 + 96 + 20 |

배율이 전부 **정수배**다. 픽셀 아트를 정수가 아닌 배율로 늘리면 격자가 화면
픽셀 사이에 놓여 흐려진다 — 보스 확대 배율, 9-슬라이스 배율과 같은 규칙이다.

행 높이 62px와 폰트 55pt는 아틀라스를 구운 값이라 못 바꾼다(14단계). 아이콘을
그 안에 앉혔고, 8축이 화면에 안 들어가는 스크롤은 유지했다.

상단 바에도 코인·별을 붙였다. 성장 행이 심볼을 쓰기 시작했으므로 상단 바도 같은
언어를 써야 한다 — 한쪽만 아이콘이면 두 화면이 다른 규칙으로 읽힌다.

### 왜 아이콘인가

14단계까지 성장 행은 글자뿐이었다. 여덟 줄이 전부 "OO 강화 Lv.N"이라 목록을 훑을
때 눈이 **글자를 읽어야만** 어느 축인지 알 수 있었다. 방치형에서 이 목록은 하루에
수십 번 보는 화면이고, 그때마다 읽게 만드는 것은 비싸다.

## D. 누락 검사 (VerifyWiring)

축을 하나 추가하면 트랙 표에는 넣지만 아이콘 표에 넣는 것을 잊기 쉽다. 그러면
그 행만 빈 사각형으로 나가는데 **여덟 줄 중 하나라서 눈에 잘 안 띈다.**

고치기 전에 검사가 나쁜 상태를 잡는지 먼저 확인했다.

```
clean:             OK
스프라이트 비움:   Growth row 'Upgrade0' has an empty icon
                   - add its track id to UiIcons.Map
오브젝트 없음:     Growth row 'Upgrade3' has no Icon object
상단 바 코인 비움: Top bar 'GoldIcon' is missing its sprite
restored:          OK
```

통과 시에는 로그를 남긴다: `[Onikiri] Row icons: 8 rows, all assigned.`

### 검사가 실제 버그를 하나 잡았다

첫 빌드에서 `StatHeader`("남은 포인트")가 **아이콘 없는 행**으로 걸렸다.

원인은 아이콘이 아니었다. 머리글이 **아무 일도 하지 않는 버튼을 달고 있었다.**
검사가 버튼 유무로 행과 머리글을 가르는데, 머리글에도 버튼이 있어 행으로 세어진
것이다.

눌러도 반응 없는 버튼은 14단계에서 눌림 상태를 넣으며 없앤 문제와 같은 종류라
버튼을 제거했다. 검사를 느슨하게 고치는 대신 원인을 고쳤다.
