## 왜 스탯이 한 치도 안 움직이는가 — 평균 보존 설계

이 스텝의 핵심 제약은 "순수 데이터/연출 — 밸런스 무관"이었다. 그런데 잡몹
스탯은 겉보기와 달리 풀에 묶여 있다: 보스 체력과 방치 보상이 스포너의
**스폰 가중 평균**에서 유도된다 (`BossFight.BossMaxHealth` →
`EnemySpawner.AverageBaseHealth` → `StageCurve.BossHealthForStage`).
풀의 구성을 바꾸면 평균이 움직이고, 평균이 움직이면 지역을 넘는 순간 보스
체력이 바뀐다 — 그것은 밸런스 변경이다.

기존 필드는 3종(w3: HP8/골드2, w5: HP14/골드5, w1: HP34/골드18)이라 평균이
**HP 128/9 = 14.222, 골드 49/9 = 5.444**였다 (8단계부터 시뮬 앵커).
지역당 2종으로 재편하면서 이 평균을 정확히 맞추는 정수해를 골랐다:

```
w5 × (HP12, 골드5) + w4 × (HP17, 골드6)
  → HP  (5×12 + 4×17)/9 = 128/9  ✓
  → 골드 (5×5  + 4×6 )/9 =  49/9  ✓
```

모든 지역이 같은 스탯 구조를 쓰므로 **어느 지역 풀로 평균을 내도 기존 값이
나온다.** 시뮬레이션·밴드 테스트가 수정 없이 통과하는 이유이고, 이것이
우연히 통과한 것이 아님을 못 박으려고 RegionMobPoolTests가 **풀별로** 평균을
다시 잰다 — 전체 평균 검사(StageSimulationTests)는 8종을 한 번에 섞으므로
한 풀이 후하고 다른 풀이 박해도 상쇄되면 통과하기 때문이다.

같은 종이 지역에 따라 다른 스탯을 갖는 경우가 생긴다(지역 3의 히토다마는
HP12, 지역 4의 히토다마는 HP17). 화면에는 스탯이 안 뜨고 스테이지 배수가
지배하므로 보이지 않는 차이다 — 가중치가 정의 애셋 안에 있어서 같은 애셋을
두 풀이 다른 가중치로 쓸 수 없고, 그래서 지역 4는 `_Den` 접미사의 별도
애셋이다 (Enemy_Onigashira_Den, Enemy_Hitodama_Den).

## 데이터 구조 — 배경 세트와 같은 모양

- **RegionMobSet** (신규 SO): `EnemyDefinition[] mobs` 한 벌.
  `Data/Mobs/RegionMobs_1~4.asset`, 빌더 생성물이라 매 빌드마다 덮어쓴다.
- **RegionConfig.mobs** (신규 필드): 비우면 앞 지역 풀을 그대로 쓴다 —
  배경(`background`)과 같은 규칙.
- **RegionMobSwitcher** (신규, Battle GO): `StageProgress.Changed` 구독,
  지역이 바뀌면 `EnemySpawner.SetDefinitions` + `BossFight.SetStageBossDefinitions`.
  배경 스위처와 달리 연출이 없다 — 스폰 풀 교체는 화면 밖의 일이다.
- 씬에 굳는 시작 풀은 지역 1이다. 세이브 복원 시 스위처의 첫 Refresh가
  현재 지역 풀로 바꾼다 (배경과 같은 타이밍).

이미 서 있는 요괴는 교체하지 않는다. 지역은 보스를 잡아야 넘어가고 보스전
진입이 필드를 비우므로, 정상 경로에서는 빈 필드에 새 풀이 채워진다.
스위처가 ClearField를 부르지 않는 이유는 보스전 도중 스테이지가 바뀌는
경로에서 보스까지 치워버리기 때문이다 — 테스트 패널의 지역 점프 버튼만
파밍 중일 때 필드를 비운다(보상 없는 ClearField라 골드가 새지 않는다).

## 확대판 보스가 지역을 따라오는 이유

챕터 정예(Boss_Elite)와 일반 스테이지 보스는 `baseMob`이 비어 있어
`BossFight.StageBossDefinition()`이 `stageBossDefinitions`에서 스테이지로
하나를 고른다. 스위처가 이 배열을 스포너와 **같은 풀로** 갈아끼우므로
"방금까지 베던 놈의 우두머리"가 지역마다 자동으로 성립한다 — 확대/틴트
규칙(2배, 정예 청색/일반 분홍)은 기존 그대로다. 스포너만 바꾸고 이쪽을
두면 잡몹은 새 지역인데 확대판만 옛 지역 몹이 되는 반쪽 교체가 된다.

## Inimig 클립 실측 — 카사오바케만 태그가 없다

Aseprite 태그가 전부 무명(Tag/Tag_0…)이라 정체를 화면 실측으로 확정했다
(콘택트 시트를 구워 프레임 단위로 확인). 팩 공통 규칙: **2프레임 = 피격,
6프레임 = 사망**(하양 플래시 → 붕괴 → 먼지).

```
Inimig (3)  idle=Tag(8)   death=Tag_2(6)   비행 오니 두상, 파이어볼 클립은 미사용
Inimig (6)  idle=Tag(8)   death=Tag_0(6)   털짐승
Inimig (7)  idle=Tag(12)  death=Tag_0(6)   기존 Mossback 그대로
Inimig (8)  idle=Tag(8)   death=Tag_1(6)   버섯
Inimig (2)  태그 1개뿐 (43프레임 중 12프레임만 태그) ← 문제의 개체
```

Inimig (2)의 유일한 태그는 뒤쪽 구간(F35~46, 구르기 섞임)이고 사망이 클립으로
안 나온다. 미태그 프레임도 스프라이트로는 전부 임포트되므로(임포터가
Frame_N으로 이름 붙임, 중복 프레임은 번호를 건너뜀), 빌더에 **스프라이트
이름 범위 폴백**(`FramesByName`)을 추가해 실측으로 확정한 구간을 직접 집었다:
idle = F0~7(깡충 뛰기), death = F28~33(다른 몹과 같은 하양→붕괴→먼지 6프레임).
걷기 클립은 전 종 비워뒀다 — 기존 잡몹과 같은 규칙(idle 폴백, 부유/도약형)이고
무명 태그를 걷기로 오인 배선하는 위험을 지지 않았다.

제외 개체: **Inimig (1) 초롱**은 지역 1 피날레(외눈 등롱)의 원본이라 잡몹
풀에서 뺐다(가중치 0으로 강등, Boss_CyclopsLantern의 baseMob 참조는 유지).
**Inimig (9)**는 다크 사무라이 보스 시트다. 이제 팩 아홉 중 여덟이 쓰인다
(미사용은 Inimig (9) colo 1 하나).

## 검증

- **빌드**: Build Combat Content 1회 — 8종 정의 + 풀 4개 생성, VerifyWiring
  통과(스위처 배선, 풀별 idle/death 존재, 스포너 시작 풀 = 지역 1 검사 추가).
  디스크 씬 grep으로 스위처 GUID·지역 1 풀 참조 확인 (33단계 규칙).
- **테스트**: 305/305. 신설 RegionMobPoolTests — 풀별 평균 = 14.222/5.444,
  지역 1~3 종 상호 배타(아트 텍스처로 비교), 지역 4 = 지역 3 재활용 명시,
  초롱 풀 제외. StageSimulationTests의 정의 수 앵커는 3 → 8로 갱신.
- **실기**: 지역 1~4 파밍 각 1장. 좌향(플레이어 쪽) 응시·발선·부유 높이·사망
  파편까지 화면 확인. 카사오바케 사망(이름 범위 프레임)도 파편으로 확인됨.
