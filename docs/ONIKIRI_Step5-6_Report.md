| 용도 | 클립 |

타격을 4종으로 둔 이유는 다음 항목과 직결됩니다 — 같은 파형이 초당 여러 번 반복되면 그것 자체가 피로의 원인입니다.

### 2.2 사운드 피로 대책 (요청 3번)

| 장치 | 값 | 근거 |
|---|---|---|
| 피치 랜덤 | 타격 **0.94~1.06** (±6%) | 요청 범위 ±5~8% 내 |
| 처치음 피치 | 0.78~0.88 | 타격음과 음역을 분리 |
| 동시 재생 상한 | **보이스 4개** 링 버퍼 | 요청대로 |
| 최소 재생 간격 | 타격 **40ms** / 처치 20ms | 요청대로 |

**모든 판정은 `Time.unscaledTime` 기준입니다.** 스케일 타임을 쓰면 히트스톱(시간 정지) 동안 들어온 타격이 정지 해제 순간 **한꺼번에 통과해** 오히려 최악의 순간에 소리가 뭉칩니다.

실측 검증 (한 프레임 내):

```
PlayHit  20회 호출 -> 19회 차단, 1회 재생
PlayKill 10회 호출 ->  9회 차단, 1회 재생
30회 연속 호출에도 동시 재생 보이스는 4개 상한 유지
```

### 2.3 처치음 분리 (요청 4번)

전용 뱅크를 두되, **뱅크가 비어 있으면 타격음을 0.78~0.88로 피치다운해 대체**합니다. 클립이 도착하기 전에도 처치와 타격이 청각적으로 구분되고, 나중에 전용 클립을 넣으면 코드 변경 없이 승격됩니다.

### 2.4 임포트 설정 자동 적용

팩 기본값은 44.1kHz **스테레오 Vorbis**였습니다. 이 게임에서는 셋 다 낭비입니다.

| 설정 | 값 | 이유 |
|---|---|---|
| Force To Mono | 켬 | `spatialBlend = 0`(2D)이라 두 번째 채널은 어차피 버려짐 |
| Compression | ADPCM | 1초 미만 클립에 Vorbis 디코드 비용은 과함 |
| Load Type | DecompressOnLoad | 재생 시점 디코드 지연 제거 |
| Preload | 켬 | 첫 타격에서 끊기지 않게 |

## 3. B. 화면 흔들림 + 히트스톱 스케일링

### 3.1 ScreenShake — 배경이 흔들림을 상쇄하던 문제

3px / 0.1초, **픽셀 스냅**으로 흔듭니다. 픽셀 아트에서 소수점 오프셋으로 흔들면 스프라이트 격자가 화면 픽셀 사이에 놓여 한 프레임씩 뭉개집니다.

문제는 `BattleStageLayout`이 **매 프레임 카메라를 따라 배경을 재배치한다**는 것이었습니다. 카메라가 흔들리면 배경도 같이 따라가서 **화면상으로는 아무 일도 일어나지 않습니다.** → 레이아웃이 흔들림이 제거된 `CameraBasePosition`을 따르도록 분리했습니다.

흔들림은 `unscaledDeltaTime`으로 진행합니다. 히트스톱과 **동시에** 걸려야 하는데 스케일 타임이면 정지 중에 흔들림도 함께 멈춰 버립니다.

### 3.2 히트스톱 스케일링 (요청 3번)

요청하신 `min(0.07, 0.3/attackSpeed)` 규칙을 `CombatFeel.ScaledDuration(base, budget, aps)`으로 일반화했습니다. **"고정 길이"가 아니라 "초당 화면 점유 예산"** 개념입니다.

| 효과 | 기본 길이 | 초당 예산 | 교차점 |
|---|---|---|---|
| 히트스톱 | 0.07초 | 0.3 | **4.29회/초** |
| 화면 흔들림 | 0.10초 | 0.4 | 4.0회/초 |

교차점 아래에서는 설계한 길이를 그대로 쓰고, 위에서는 자동으로 짧아집니다. 방치형은 결국 초당 10회에 도달하는데, 그때 0.07초 고정이면 **전체 시간의 70%가 정지 상태**가 되어 게임이 고장난 것처럼 보입니다.

## 4. 적 3단 위계 (요청 4번 — Inimig(7) 교체 검토)

교체가 아니라 **3단 위계로 확장**했습니다. 한 종류만 나오면 방치 화면이 금방 단조로워집니다.

| 티어 | 아트 | 크기 | 가중치 | 체력 | 이동 | 골드 |
|---|---|---|---|---|---|---|
| 필러 | Inimig(4) 히토다마 | 32×20 | 3 | 8 | 1.25 | 2 |

| 정예 | Inimig(1) 등롱 | 47×40 | 1 | 34 | 0.8 | 18 |

요청하신 Inimig(7)이 **전투의 대부분을 차지하는 일반 몹**입니다. 등롱은 의도적으로 사무라이보다 크므로 가중치 1로 드물게 유지했습니다.

`artBottomOffset`은 티어마다 자동 측정됩니다 (1.0625 / 0.875 / 0.6563 units). 4단계에서 상수 하나로 두려다 실패했던 값이라, 이번에는 처음부터 스프라이트에서 뽑습니다.

> **보고서 정정** — 4단계 보고서의 적 크기표를 `32×20`처럼 **높이×너비**로 적어 히토다마가 20px짜리로 읽혔습니다. 실제로는 **32px 높이**이고, 주인공(34px) 대비 0.94배입니다. Inimig(7)은 0.85배. 위 표는 폭×높이로 통일했습니다.

## 5. 5단계 — 피격/사망 + 골드 획득

### 5.1 PlayerWallet — 첫 코인부터 BigDouble

`long`으로 시작해 나중에 승격시키는 방식을 쓰지 않았습니다. 방치형은 플레이 몇 시간이면 `long` 범위를 넘고, 그 시점에 숫자 타입을 바꾸면 **잔액을 읽는 모든 시스템을 동시에 손대야** 합니다.

`Gold` / `LifetimeGold`(환생 계산용 누적) / `TrySpend`(감당 가능할 때만 소비) / `SetBalance`(세이브 복원 경로) 를 갖췄습니다.

### 5.2 보상 지급 시점 — `Killed` vs `Died`

이벤트를 둘로 나눴습니다.

| 이벤트 | 시점 | 용도 |
|---|---|---|
| `Killed` | 체력 0이 된 **그 프레임** | **골드 지급**, 처치음, 데미지 숫자 강조 |
| `Died` | 사망 애니메이션 종료 | 풀 반환 |

`Died`에 보상을 붙이면 사망 연출 0.5초만큼 늦게 들어옵니다. 방치형에서 **때린 것과 숫자가 오르는 것 사이의 지연은 곧바로 손맛의 손실**입니다.

### 5.3 HUDCurrency

`GoldChanged` 이벤트 기반으로만 갱신합니다. 매 프레임 `BigDouble`을 문자열로 포맷하는 것은 방치형에서 상시 발생하는 GC 부담입니다.

## 6. D. 한글 폰트 (갈무리) — 요청보다 먼저 처리

### 6.1 요청 사양 대비 결과

| 항목 | 요청 | 결과 |
|---|---|---|
| Atlas Render Mode | RASTER_HINTED (SDF 금지) | ✅ 그대로 |
| Atlas 필터 | Point | ✅ 그대로 |
| 셰이더 | TextMeshPro/Bitmap | ✅ 그대로 |
| 문자셋 | 전체 11,172자 금지 | ✅ **205자**만 |
| 메뉴 재실행 | `Onikiri/Art/Rebuild Font Charset` | ✅ 그대로 |
| Sampling Point Size | **11** | ⚠️ **33** (아래) |
| Padding | **0** | ⚠️ **1** (아래) |
| 표시 크기 | 11의 배수 | ⚠️ **33의 배수** |

### 6.2 ⚠️ 11pt / Padding 0을 지킬 수 없었던 이유

지시대로 11pt·Padding 0으로 구웠더니 **글자가 눈에 띄게 깨졌습니다.** 원인을 측정한 결과:

```
글리프 메트릭 : 10 x 11 px   <- TMP가 이 크기로 쿼드를 만든다
패킹된 rect    :  9 x 10 px   <- 실제로 샘플링하는 영역
```

TMP는 **메트릭으로 쿼드를 그리고 rect를 샘플링**합니다. 1px 어긋나면 모든 글리프가 약 10/9로 늘어나고, Point 샘플링이 픽셀 행을 복제하거나 누락시켜 글자 형태가 무너집니다.

- **Padding 1** → `rect = 메트릭 + 2`가 되어 매핑이 정확해집니다. 래스터라 번짐은 없고 글리프당 투명 여백 1px만 씁니다.
- **33pt(3배) 래스터** → 픽셀 폰트의 외곽선은 축 정렬 사각형이라 정수배로 구우면 정확히 3×3 블록이 나오고 반올림 오차가 사라집니다.

그 결과 **표시 크기가 11의 배수가 아니라 33의 배수**가 됩니다. 44는 아틀라스를 1.33배 리샘플하는 것이라 오히려 흐려집니다. `UI/PixelFontSizes.cs`에 33(본문) / 66(제목)만 상수로 열어두고, UI 코드가 숫자를 직접 적지 못하게 했습니다.

### 6.3 용도 분리 (요청 12번)

| 용도 | 폰트 | 크기 | 아틀라스 |
|---|---|---|---|
| 한글 UI | Galmuri11 | 33 / 66 | 33pt (11×3) |
| 데미지 숫자 | ThaleahFat | 48 | 48pt (16×3) |

Thaleah의 설계 크기 16px은 동봉된 레거시 `ThaleahFat.fontsettings`의 `m_FontSize`에서 확인했습니다. 이쪽은 rect == 메트릭이 정확히 떨어져 Galmuri 같은 1px 오차가 없습니다.

문자셋도 분리했습니다. Thaleah는 라틴 전용이라 숫자·구분자·`K M B T`·알파벳 44자만 굽습니다. 전체 UI 문자셋을 먹이면 **한글 글자마다 누락 경고가 쌓입니다.**

### 6.4 문자셋 추출

`Data/UIStrings.txt` + 프리팹·씬의 모든 TMP 텍스트를 훑어 유니크 글자만 모읍니다. 한글 11,172자 전체 대비 **아틀라스 1페이지**로 끝납니다. 새 문구를 추가하면 메뉴 한 번으로 다시 굽습니다.

## 9. 이번에 잡은 버그

### 9.1 소리가 안 들린다 — 씬에 AudioListener가 없었다 (심각)

**증상**: 코드도, 클립도, 임포트 설정도, 피로 대책 실측도 전부 정상인데 소리가 나지 않음.

**원인**: `MainSceneBuilder`가 카메라를 **직접 만들면서** AudioListener를 빠뜨렸습니다. Unity가 기본 생성하는 Main Camera에는 딸려 오지만 손으로 만든 카메라에는 없습니다.

**왜 검증을 통과했는가**: 리스너가 없어도 `AudioSource.Play()`는 성공하고 `isPlaying`도 `true`를 반환합니다. 소리만 출력에 도달하지 않습니다. **"코드가 동작한다"가 "들린다"를 증명하지 못하는** 전형적인 경우였습니다.

**조치** — 세 곳:
1. `MainSceneBuilder` — 카메라 생성 시 리스너 추가
2. `BattleContentBuilder.EnsureAudioListener()` — 기존 씬 복구용 (Rebuild Main Scene은 스테이지를 초기화하므로 별도 경로 필요)
3. `VerifyWiring()` — 리스너 부재 검사 추가. 같은 실패가 다시 조용히 지나가지 못함

**실측 확인** (플레이 모드, `AudioListener.GetOutputData`):

```
리스너 출력 최대 진폭 = 0.422447
소스 출력 최대 진폭   = 0.101578
재생 중이던 틱        = 120 / 120
```

`isPlaying` 같은 간접 지표가 아니라 **리스너에 도달한 실제 파형**입니다.

> 측정 중 처음 두 번은 0이 나왔는데, `Thread.Sleep`으로 메인 스레드를 막고 샘플링했기 때문입니다. 프레임이 돌지 않으면 출력 버퍼가 갱신되지 않습니다. `EditorApplication.update` 훅으로 실제 프레임 위에서 재야 유효한 값이 나옵니다.

### 9.2 공격속도가 초당 2회에서 막혀 있었다 (심각)

**증상 없음** — 사운드 피로 대책을 실측하다 발견했습니다.

공격 애니메이션이 7프레임 14fps = **0.5초 고정**이라, `attacksPerSecond`를 12로 올려도 실제 공격은 **초당 2회에서 멈췄습니다.** 방치형의 핵심 성장 축인 공격속도가 스탯을 올려도 무의미해지는 상태였습니다.

→ 스윙 길이를 공격 간격에 맞춰 압축: `attackDuration = min(baseDuration, 1/aps)`. 초당 30회에서 0.0333초 확인. 스탯이 오르면 스윙도 눈에 띄게 빨라져 **연출상으로도 맞습니다.**

### 9.3 TMP Essential Resources가 임포트된 적이 없었다

`TMP_Settings`가 null이라 **모든 TMP 텍스트가 렌더링 불가** 상태였습니다. 골드 HUD를 붙이려는 순간 드러났습니다. → 임포트 + `Onikiri.Runtime.asmdef`에 `Unity.TextMeshPro` 참조 추가.

### 9.4 배경이 화면 흔들림을 상쇄

§3.1 참조. 흔들림 코드는 정상 동작했는데 화면상으로는 아무 일도 일어나지 않았습니다.

### 9.5 확인 범위 실수 2건 (사용자 지적)

- **Thaleah 폰트** — 이미 `Assets/Thaleah_PixelFont/`에 있었습니다. Desktop 에셋 폴더와 Downloads만 확인하고 `Assets/` 자체를 다시 훑지 않았습니다.
- **RPG Essentials SFX** — 이미 `Assets/Leohpaz/`에 있었습니다. 같은 원인.

프로젝트 안을 먼저 확인하지 않고 "없다"고 판단한 것이 두 번 반복됐습니다.
