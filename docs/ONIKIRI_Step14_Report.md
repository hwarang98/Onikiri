# ONIKIRI 14단계 보고서 — UI 스킨 개편 (Kenney Pixel UI)

작업일: 2026-08-06
테스트: EditMode **181/181 통과** (13단계와 동일 — UI 스킨은 테스트를 늘리지 않는다)

12단계에서 에셋 대기로 미뤄둔 **12-3**을 닫는다. 다만 스펙의 전부는 아니고,
못 한 두 덩어리와 그 이유를 아래에 적었다.

---

## 요약 — 이번 변화의 크기

**화면에서 눈에 띄는 변화는 작다.** 스크린샷 두 장을 나란히 놓아야 보이는
수준이고, "전면 개편"이라기보다 **재질만 입힌 것**이다.

| | 전 | 후 |
|---|---|---|
| 상단 바 | 글자가 배경 위에 그냥 떠 있음 | 어두운 판이 깔림 |
| 성장 행 | 단색 사각형 | 테두리 + 모서리 못 자국 |
| 버튼 | 단색 사각형 | 테두리 + **눌림 상태** |
| 잠긴 탭 | 단색 블록 | 안으로 파인 프레임 |
| EXP·체력 바 | 단색 | 파인 프레임 안에 채워짐 |

팔레트·레이아웃·위치·폰트·글자 크기는 **전부 그대로**다.

가장 큰 변화는 스크린샷에 안 나오는 **눌림 상태**다. 13단계까지 버튼은 눌러도
색조차 바뀌지 않았고, 모바일에서 그것은 "안 눌렸나?"로 읽혀 같은 자리를 두 번
누르게 만든다.

---

## 1. 임포트

`Assets/ThirdParty/UI/KenneyPixelUI/` — Kenney Pixel UI Pack, **CC0**.
`License.txt`를 함께 넣었다. 38개 파일, 179KB.

`Onikiri/Art/Build Pixel UI Pack` 메뉴가 9-슬라이스 테두리를 찍는다.

```
9-slice sprites: 33/33 bordered
  Ancient: 12   (brown/grey/tan/white x 기본·인레이·눌림)
  Colored: 10   (blue/green/grey/red/yellow x 기본·눌림)
  Outline:  8
  기타:     3   (list, space, space_inlay)
```

- 48x48 → 테두리 16 (48 = 16+16+16)
- 44x44 인레이 → 테두리 14 (44 = 14+16+14)

**파일 이름이 아니라 크기로 가른다.** 이름에 기대면 팩이 이름을 바꿨을 때
조용히 틀린 값이 들어간다.

### 왜 테두리를 따로 찍는가

기존 `PixelArtImportPostprocessor`가 포인트 필터·무압축·PPU 32까지는 해준다.
그런데 **`spriteBorder`는 못 찍는다.** 그 값이 비어 있으면 `Image.type = Sliced`가
아무 일도 하지 않고, 패널을 늘릴 때 테두리와 모서리 장식이 통째로 늘어난다 —
픽셀 아트에서 그것은 곧 흐려짐이다.

팩 원본을 고치지 않고 임포트 단계에서 해결한다. 원본을 손대면 팩을 다시 받았을 때
무엇을 고쳤는지 알 수 없다.

### 안 한 것 — 스프라이트시트

16x16 타일 시트(체크박스·화살표·슬라이더·말풍선)는 **자르지 않았다.**
이번에 필요한 것은 패널과 버튼이고, 400칸을 전부 자르면 쓰지 않을 스프라이트가
애셋 목록을 채워 필요한 것을 찾는 일이 더 비싸진다. 화살표가 필요해지면 그때
자른다.

## 2. UiSkin — 색을 한 곳으로

13단계까지 색상값이 빌더 세 곳에 흩어져 있었다. `RowColor`(UpgradePanelBuilder),
`PanelColor`(BossContentBuilder), `PopupBoxColor`(BattleContentBuilder)가 **전부
같은 #3A3550**이었고, 하나를 바꾸려면 셋을 찾아야 했다.

`UiSkin`이 팔레트와 판 적용을 관장한다. `ApplyPanel(image, sprite, tint)`와
`ApplyButton(button, target)` 둘이 입구다.

스프라이트가 없으면 색만 칠하고 끝낸다. 팩이 빠진 프로젝트에서도 화면이 13단계와
같은 모양으로 뜨고, 그 상태가 "UI가 깨졌다"로 보이지 않는다.

---

## 3. 실패한 접근과 원인 — 흰 판을 물들였더니 테두리가 사라졌다

처음 계획은 중립적인 `Ancient/white` 판을 게임 팔레트(#3A3550)로 물들이는
것이었다. 그러면 지금 화면을 유지하면서 테두리만 얻는다고 봤다.

**결과는 테두리가 보이지 않는 화면이었다.** 원인을 픽셀로 쟀다.

```
        테두리   안쪽   대비
white    0.80    0.90   +0.10
grey     0.48    0.54   +0.07
tan      0.60    0.71   +0.12
brown    0.57    0.44   -0.13   <- 유일하게 테두리가 더 밝다
```

`Image.color`는 곱연산이라 **자체 대비도 함께 줄인다.**

```
안쪽 0.90 x 0.21 = 0.19
테두리 0.80 x 0.21 = 0.17
남는 차이 0.02  -> 눈에 보이지 않는다
```

보스 확대판 틴트에서 겪은 것과 정확히 같은 함정이다(11단계: "어두운 틴트는
곱연산이라 스프라이트를 더 어둡게만 만든다"). 그때는 아트가 검은 덩어리가 됐고
이번에는 테두리가 사라졌다.

### 고른 답 — brown을 자줏빛으로 누른다

`brown`은 팩에서 유일하게 **테두리가 안쪽보다 밝다**(0.57 대 0.44). 곱셈은
그 관계를 뒤집지 못하므로, 어둡게 눌러도 테두리가 남는다.

```csharp
public static readonly Color Row = new Color(0.46f, 0.50f, 0.94f, 1f);
```

나무 판을 자줏빛으로 눌러 13단계까지 쓰던 #3A3550 근처로 되돌린다.

**중간에 나무색 그대로도 시도했다.** 따뜻한 황갈색 패널이 배경의 토리이·탑과
같은 재질이라 어울릴 것으로 봤는데, 실제로는 자주색 밤 배경과 부딪혀 화면의
절반이 다른 게임처럼 보였다. 되돌렸다.

나무 질감으로 다시 가려면 `UiSkin.Row`를 `Untinted`로 한 줄 고치면 된다.

---

## 4. 잡은 버그 — 잠긴 탭이 새까맣게 죽었다

같은 곱연산 함정의 두 번째 사례다.

`LockedTab.Refresh`가 런타임에 `background.color`를 **최종 색**(#2A253C)으로
덮어쓰고 있었다. 13단계까지는 배경이 단색이라 그것이 맞았지만, 배경이 이미
어두운 인레이 판이 되자 한 번 더 눌려 검은 사각형이 됐다.

필드의 의미를 **틴트**로 바꾸고 빌더가 `UiSkin`에서 가져와 적는다. 값이 두 곳에
있으면 팔레트를 바꿀 때 한쪽만 고쳐진다.

## 5. 적용 범위

| 화면 요소 | 판 | 틴트 |
|---|---|---|
| 성장 패널 행 | brown | Row (자줏빛) |
| 스탯 증폭 행 | brown | Row |
| 상단 바 배경 | brown | Chrome (행보다 어둡게) |
| EXP 바 배경 | brown_inlay | InlayTint |
| 보스/플레이어 체력 바 배경 | brown_inlay | InlayTint |
| 보스 도전 버튼 | brown | Danger (붉은 쪽) |
| 레벨업 버튼 | brown | Good (초록 쪽) |
| 하단 잠긴 탭 | brown_inlay | InlayTint x 0.7 |
| 오프라인 팝업 / 받기 버튼 | brown | Row / Good |
| 보스 실패 문구 판 | brown | Row |

동작 버튼의 색은 **최종 색이 아니라 틴트**다. 한 채널을 1.0 근처에 두는 것이
중요하다 — 세 채널을 모두 낮추면 그냥 어두워질 뿐이고 테두리가 사라진다.

팩의 Colored 세트(주황·라임)를 그대로 쓰는 방법도 있었지만 만화풍이라 이 게임의
픽셀 배경과 붙지 않는다. 나무 판을 붉은 쪽/초록 쪽으로 밀면 **물들인 나무**가
되고, 재질이 나머지 UI와 같은 채로 색만 갈린다.

### 배율

아트 픽셀 하나를 캔버스 픽셀 **2개**로 그린다(`UiSkin.PixelScale`). 정수여야
한다 — 픽셀 아트를 정수가 아닌 배율로 늘리면 어떤 픽셀은 두 칸, 어떤 픽셀은 세
칸이 되어 테두리가 울퉁불퉁해진다. 보스 확대 배율을 정수로 묶어둔 것과 같은
규칙이다.

3배(테두리 48px)는 행 안쪽이 너무 좁아져 탈락했다.

## 6. 못 한 것

### 아이콘 행 템플릿 — 팩에 아이콘이 없다

12-3 스펙은 "아이콘 행 템플릿"을 요구했고 `4416 RPG Icons`를 지목했다.
Kenney Pixel UI Pack에는 **RPG 스탯 아이콘이 없다** — 패널, 버튼, 체크박스,
화살표, 슬라이더, 말풍선, 커서뿐이다. 칼날·체력·치명타 아이콘을 붙일 수가 없다.

행 레이아웃을 그대로 둔 것도 이것과 묶여 있다. 행 높이 62px와 폰트 55pt는
아틀라스를 구운 크기라 못 바꾸고, 8축이 화면에 안 들어가 스크롤이 들어간
상태다. 아이콘이 들어오면 그 제약 안에서 행을 다시 짜야 한다.

**아이콘 팩이 필요하다.**

### 탭 구조 (강화/성장/승급) — 보여줄 화면이 없다

지금 만들면 탭 셋 중 둘이 빈 화면이다. 승급은 12단계 스펙에서 범위 밖으로
지정됐다.

잠긴 탭을 "눌리는데 빈 화면"이 아니라 안 눌리게 둔 것과 같은 판단이다 —
탭 전환은 보여줄 두 번째 화면이 생길 때 만든다.
