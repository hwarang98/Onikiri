## E3-1. 깊이 - 값 등가 재스케일과 그것이 가르쳐준 것

### 여덟 배 미세화 (공격력·치명타피해·체력·회복)

옛 한 레벨 = 새 여덟 칸: step^8 = 옛 step, growth^8 = 1.15, 기준 비용은
누적 골드가 같아지는 연속체 등가값. 골드와 파워의 관계가 보존되므로
밸런스는 그대로여야 했다 - **그런데 아니었다.**

    실측: 코리더 여유 +27% 균일 상승, 10개 스테이지 밴드 위반

등가 수식은 완벽했다(누적 비용 동일을 대수로 확인). 원인은 **이산
granularity**다 - 미세 칸은 지갑을 끝전까지 즉시 소진해 복리를 앞당기고,
코스 칸은 다음 덩어리를 기다리며 골드를 놀린다. 이분법 실측으로 4축
미세화가 +16~45%, 치명타 미세화가 st10에 -12%(초반 골드가 치명타로 더
흘러 후불 이득)를 만들었다.

처방: **기준 비용에 이산 보정**(4축 x1.3, 치명타 x1.2)을 얹어 앵커를
+-3%로 복원했다. "코리더 비트 불변"은 레벨 격자가 바뀐 순간 정의상
불가능하고, 새 격자의 앵커(1.5232/1.4880/1.3777/2.3365)를 테스트가
0.01 허용으로 고정한다. 밴드 위반은 0이다.

공격속도(아트 상한 Lv.32 MASTER)와 골드 획득(밴드 손잡이 x1.25)은
미세화하지 않았다 - 전자는 상한의 근거가 골드가 아니고, 후자는 깊이가
아니라 회수 시간이 정체성이다.

### 치명타 확률 - 값은 한 결, 비용은 두 결

    값   Lv.1 = 12%  ->  +0.088%p/칸 균등  ->  Lv.1000 = 정확히 100%
    비용 1결: 코리더 등가 (0.199골드, x1.0249/칸) - 60% 문턱(Lv.546)까지
         2결: 도약 x3.5e8 뒤 x1.0315/칸 - 문턱부터 만렙까지

1결은 42단계까지의 곡선을 값 등가로 미세화한 것이다(시뮬 실측으로 곡선
추종 플레이어가 st22에 60%에 서 있으므로, 여기가 바뀌면 코리더가
무너진다). 2결이 60% -> 100%를 무한 구간의 콘텐츠로 만든다: 문턱 통과
st60, **Lv.1000 완성 st87** - 천장과 f2p가 같은 시점이다(골드 기반이라
체인은 과금벽이 아니다). MaxLevel은 상수 1000이 근원이고 스텝이
유도값이다 - 나눗셈 유도는 부동소수점에서 999로 떨어질 수 있다.

UpgradeTrack에 관문(2상 비용) 필드가 생겼고 치명타만 쓴다. 비용 인덱스
관례(CostAtLevel(L) = L+1로 가는 가격)에 1차 구현이 물렸던 자리라 곡선과
트랙이 같은 식을 쓰는지 주석으로 못 박았다.

## E3-2. 심화 축 - 초월 치명타 + 연격 (Lv.1000의 문 뒤)

| 축 | 형태 | 비용 | 끝 |
|---|---|---|---|
| 초월 치명타 | 피해 전체 x1.00186/칸 (복리) | 9.05e13, **여덟 칸 묶음 x2.0** | 없음 - 무한 골드 싱크 |
| 연격 | 타격마다 +0.1%p/칸 확률로 한 번 더 | 7.12e12, x1.0356/칸 | **Lv.1000 = 확정 2연격 MASTER** |

연격을 고른 이유(발도 심득 대신): 메타 증폭은 요도 혼 축과 곱이 겹치고,
연격은 전투 화면에 실물(추가 타격·자기 숫자)이 생겨 체감 검증이 된다.
추가타는 온전한 한 타다 - 치명타·초월을 상속하고 평타·오의 모두에서
구른다(PlayerCombat 두 자리). 실측 성장 궤도: st100에 초월 Lv.213 /
연격 Lv.501, st150에 연격 Lv.1000 완성 - "수천 레벨" 스펙 그대로다.

초월의 비용 증가율이 공통 규칙(1.15)을 깨는 이유: 공통 증가율의 무상한
복리 축은 균형점에서 x1.06/스테이지의 영구 기울기를 만들어 여유를 지수
발산시킨다(1차 실측 st200 리프트 x10310). 묶음 x2.0이면 드립이
x1.012/스테이지로 줄고, 이것은 보정이 전량 흡수한다.

# E-3 수정 후속 — 강화 비용: 소수 제거(최소 1골드) + 전반 상향 x3.5

작업일: 2026-08-10
테스트: EditMode **334/334 통과** (328 + 신규 6: UpgradeCostTests)
세이브: 변경 없음 (레벨은 그대로, 비용은 유도값이라 마이그레이션 불필요)

## 1. 소수·1골드 미만 — 0건

규칙의 단일 출처는 신설 `UpgradeCost`다.

    Quantize: 1 미만 -> 1골드, 이후 사사오입 정수. 10^15 위는 double의
    정수 해상도 밖이라 항등(끝전이 표시 밖).

- 곡선 statics(시뮬·효율 지표)와 UpgradeTrack(씬의 버튼)이 **같은 함수**를
  지난다 - 관문 축(치명타 확률)의 두 구간 비용까지 Lv.1000 전 구간 대조
  (`CritRateTrack_MatchesTheCurveAcrossTheWall`).
- 전 축 전 레벨 소수 0건·1골드 미만 0건·계단 하강 0건을 테스트가 고정
  (`EveryAxis_EveryLevel_CostsWholeGoldAndAtLeastOne` / `CostNeverStepsDown`).
- 표시: 43단계의 "100 미만은 소수" 처리 삭제 - 비용은 언제나
  `NumberFormatter.Format`(정수 축약 K/M/B…)이다. 실기 확인: 공격력
  744.3K / 공격속도 75 / 치명타 확률 9골드(Screenshots/screenshot-20260810-174713).
- 테스트 패널 강화 절에 다음 칸 비용 표시 추가 - 소수가 새면 "?!"가 붙는다.

## 2. 상향 — 전 축 일괄 x3.5, 상한은 st2가 정했다

기준 비용 일괄 x3.5 (`UpgradeCost.RaiseScale`). 축 사이 비율(치명타 피해
= 확률의 2배, 체력/회복 정수 탐색값, 이산 보정 x1.3/x1.2)이 전부 조율된
값이라 배율 하나로 올려 관계를 보존했다. **골드 획득 축만 제외** - x4를
얹어보니 "해금 즉시 상한"(StagesToCeiling=0) 가정이 깨져 st6~9 여유에
크레이터(결손 x6.7)가 파였다. 그 축은 성장이 아니라 스위치(총 600골드,
이득 상한 x1.25)라 병목 상향과 무관하고, 정수화만 받는다. 심화 두 축은
함께 올랐다(초월 3.17e14, 연격 2.49e13).

첫 칸 체감 (전 -> 후):

    공격력   1.53 -> 5      치명타 확률  0.20 -> 1     체력      1.37 -> 5
    공격속도 4    -> 14     치명타 피해  0.31 -> 1     체력 회복 0.61 -> 2

st1 수입이 마리당 5.4골드이니 공격력 한 칸 = 잡몹 한 마리, 옛 한 레벨
(여덟 칸) = 잡몹 일곱 마리 몫이다. 0.1골드짜리 칸은 없다.

**왜 3.5이고 더 못 올리는가.** 완화(아래 3)는 무강화 플레이어의 보스도
가볍게 하므로, st2에서 두 요구가 마주 온다 - 코리더 바닥(여유 1.5)은
완화를 요구하고, 무강화 게이트(st2에서 막힘, 여유<1)는 완화를 막는다.
실측으로 그 창이 닫히는 지점이 x4.05다(무강화 st2 여유 0.597 x 완화
1.63 = 0.97). x4는 여유 0.6%의 칼끝이라 x3.5로 확정 - 지금 무강화 st2
여유 0.955, 코리더 st2 여유 1.54로 양쪽 다 선다. **"더"를 원하면 게이트
앵커(막히는 스테이지 2)나 초반 코리더 바닥 중 하나를 내줘야 한다.**

## 3. 여파 — 완화 곡선(여섯 번째 항, 처음으로 나누는 항)

비용 탄력이 1이라(st30 이후 여유가 정확히 1/3.6) 코리더가 통째로
가라앉는다. 램프가 아니라 **보정항 문법의 완화**로 되돌렸다:
`StageCurve.CostRaiseRelief` - 실측 결손 곡선(기준 여유/상향 여유)의
마디를 기하 보간, st30부터 평평한 3.60. 다섯 보정과 방향만 반대라
BossHealthForStage에서 나눈다.

    마디(실측): st1 1.28 / st2 1.60 / st3 2.60 / st4 3.30 / st5 4.30 /
                st8 4.90 / st10 4.43 / st11 4.10 / st15 3.89 / st20 4.08 /
                st25 3.85 / st30+ 3.60

st1~5는 기준 여유(1.87~1.97)가 아니라 **바닥 언저리(1.44~1.83)로만**
되돌렸다 - 상향의 목적이 초반 병목이므로 초반 코리더는 밴드 안에서
의도적으로 맵다. 발도 개방 실측 마디도 세 스테이지 뒤로 밀려 함께
재실측했다(TranscendCurve: 문턱 61/중간 93/착지 173, MASTER st87->90).

밴드 실측(위반 0):

    코리더(1~30)    기본·f2p 전부 밴드 안 (st1 1.78 / st10 1.52 / st11 2.44
                    / st20 1.38 / st30 1.44)
    무강화 게이트    st1 클리어 18.6초(창 12~30), st2부터 막힘 - 앵커 유지
    가속(31~50)     상수 그대로 통과
    심층(56~200)    f2p 1.73/1.42/1.16 (기준 1.4/1.25/1.08)
                    천장 10.2/7.4/5.9 (기준 13/9.5/7.2)
    수렴            5.57 -> 5.01 (-10%/100st, 기준 35%)
    f2p             st200까지 실패·사망 없음
    앵커 재기준     무력화 세계 1.5222/1.4438/1.3771/2.3413 (43단계 대비
                    st30만 -3%, 나머지 +-0.2%)

## 4. 온보딩과 알려진 대가 — "더/덜"의 재료

**온보딩 1~5: 169초 -> 241초 (+43%).** 보스는 완화가 되돌리지만 잡몹
체력에는 완화 손잡이가 없어서, 처치 감속(st5 실측 0.52s -> 2.27s)이
전부 시간으로 나온다. 3분 목표는 4분대 초반으로 재기준했고(테스트 한계
270초) - "골드가 실제 병목"의 직접 비용이다.

최전선 파밍 우위의 예외 3곳: 타격 수는 정수라 최전선에서 한 계단 뛰는
자리가 생기는데, 원래는 그 전환이 보충 간격 하한(0.4초) 아래에 가려져
있었다. 상향이 처치를 늦춰 창이 st20대로 올라왔고, 실측 역전은 f8 +1.7%
/ f23 +16.3% / f26 +16.3% 딱 세 곳(f27~st200 역전 0건, 테스트는 코리더
과도 구간만 18% 슬랙).

**배율을 움직일 때의 자.** 상한 쪽은 st2 창(x4.05)이 막고, 하한 쪽은
체감이 사라진다. 온보딩을 되찾고 싶으면 배율을 내리는 것이 유일한
손잡이다(대략 x2에서도 200초). RaiseScale을 움직이면 완화 마디·발도
마디·온보딩 앵커는 반드시 재실측이다.

## 5. 갱신된 테스트

- 보정 산수에 완화 편입: TierMultipliers / ChapterMultipliers가

# E-3 후속 — 온보딩 회복: st1~5 잡몹 체력만 하향 (비용 곡선 불변)

작업일: 2026-08-10
테스트: EditMode **337/337 통과** (334 + 신규 3: 완화 계약)
세이브: 무관 (순수 밸런스 상수, 씬 재빌드도 불필요 - 직렬화 값 없음)

## 1. 온보딩 1~5: 241초 -> **174초** (기준 169초 +3%, 목표 ±10% 안)

분해가 방향을 정했다. 초과 72초 = 잡몹 파밍 65초 + 보스 7초. 보스는
완화 곡선(CostRaiseRelief)이 이미 밴드로 되돌렸으므로 남은 몫은 잡몹
체력뿐이고, **비용 곡선(x3.5·1골드 정수)은 한 글자도 건드리지 않았다.**
3분 목표(테스트 한계 180초)가 되살아났다.

## 2. 방식 - 잡몹 전용 기하 감쇠 완화 (st6 자연 합류)

`StageCurve.MobHealth` = 원곡선 ÷ `MobHealthRelief(stage)`. 나눗값은
st1의 5.0에서 st6의 1.0까지 **기하 감쇠**라, 온보딩 실효 체력 성장이
스테이지당 1.55 x 5^0.2 = x2.13으로 균일해지고 st6에서 원곡선 값에
정확히 닿는다 - 경계 계단이 없다. 완화 구간만 정수 반올림(최소 1,
비용의 UpgradeCost와 같은 문법), st6+는 반올림조차 지나지 않는다.

    잡몹 평균 체력   st1 14.2->3  st2 22->6  st3 34->13  st4 53->28
    (전 -> 후)      st5 82->59  st6 127 (불변)
    파밍 시간/스테이지  21->4.4 / 24->6.4 / 24->9.1 / 24->12.8 / 26->19.0초

적용 지점 셋이 같은 입구를 쓴다: EnemySpawner(스폰), StageSimulation
(시뮬), GameSession(방치 수입 추정 - 파밍만 빨라지고 방치가 옛 체력을
쓰면 온보딩에서 두 벌이 갈린다). 전투 전용 테스트 씬(StageProgress
없음)은 예전처럼 정의값 그대로다.

## 3. 왜 이 완화는 밸런스를 안 건드리는가 - 그리고 실측 확인

**잡몹 처치 속도는 골드 총량과 무관하다.** 스테이지당 10마리 고정에
마리당 골드 불변이라, 빨리 잡아도 지갑은 같은 처치 지점에서 같은
금액이다. 구매 궤적이 비트 단위로 같으므로 화력·보스 여유·밴드가 전부
그대로고, 움직이는 것은 벽시계뿐이다. 하네스 재확인:

    무력화 앵커      1.5222/1.4438/1.3771/2.3413 - 완화 전과 **동일**
    코리더 여유 표    st1~30 전 값 완화 전과 동일 (밴드 위반 0)
    심층/천장/수렴    1.73/1.42/1.16 · 10.2/7.4/5.9 · 5.57->5.01 - 동일
    무강화 게이트     보스는 완화 경로 밖 - st1 18.6초 클리어, st2 여유
                    0.955로 막힘. 앵커 유지
    f2p             st200까지 실패·사망 없음
    st6+ 파밍       st6 17.1초 / st7 13.2초 - 변경 전과 동일 (비트 불변)

크기(÷5)의 상한도 실측이다: 초입을 더 내리면 시간이 거의 안 줄고
(파밍이 공격속도 하한 10/aps에 닿는다) 잡몹만 종잇장이 된다.

## 4. 알려진 대가 - 재선택 게이트가 이미 막고 있던 것

완화된 st1~5는 파밍 효율(골드/초)이 높아, 최전선 2~7에서 "되돌아가
파밍"이 이론상 우위다(실측 최악 f5/st3 +69%). **그러나 재선택 자체가
최전선 11부터다**(StageProgress.ReselectUnlockStage) - 37단계가 정확히
이 원칙("최전선이 최적은 재선택이 존재하는 모든 구간에서 참")으로
게이트를 둔 자리라, 이 역전들은 전부 도달 불가능한 세계다. 최전선
검사는 게이트 앞을 계약 밖으로 정리했고, 게이트 뒤의 역전은 E-3 수정
때의 두 곳(f23/f26 +16.3%)뿐이다.

부수 효과 하나: 완화로 st1 무강화 수입이 초당 6골드대가 되면서 골드
획득 축의 회수(64초)가 온보딩 수입에서도 밴드 안이 됐다. 온보딩에서
이 축이 안 팔리는 것은 이제 가격이 아니라 **게이트(UnlockStage=6)의
일**이다 - 21단계의 분업("등장 시점은 게이트가 정한다")이 문자
그대로가 됐고, 테스트를 그 사실로 다시 못 박았다.

## 5. 갱신된 테스트 (337 = 334 + 3)

- 신규 3 (StageProgressionTests): 완화가 st6에서 정확히 끝남(코리더
  비트 불변, 오차 0으로 대조) / 완화 구간 정수·최소 1(잡몹 12·17
  실물로) / 기하 감쇠 균일성.
- 재기준: 온보딩 174±12(한계 **180 복원**), 장비 온보딩 174, 잡몹
  반응 기점 st6(완화 구간은 분모 부적격), 최전선 검사는 재선택 게이트
  (f11) 앞을 계약 밖으로, 골드 축 온보딩 회수는 "게이트의 일" 재서술.
- 테스트 패널: 처치당 타격 줄이 완화 지난 실제 체력 + 완화 배율 표시.
