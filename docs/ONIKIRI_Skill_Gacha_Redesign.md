# 귀참 키우기 - 15종 스킬 로스터 + 스킬 뽑기 통합 재설계

> 설계 문서. 이 단계에서는 코드·씬·세이브를 수정하지 않는다.
> 모든 기존 수치는 2026-08-14 시점 코드(리듬 재조정 이후)에서 직접 읽었다.

---

## 0. 설계 원칙 - 기존 코드가 이미 못 박은 계약 위에 짓는다

이 설계는 코드 조사에서 발견한 세 가지 기존 계약을 **그대로 상속**한다.
이 계약들은 주석이 아니라 테스트로 강제되고 있다.

| 계약 | 근거 (코드) | 이 설계에 주는 제약 |
|---|---|---|
| **뽑기는 파워를 팔지 않는다** - 폭(스킬 수)과 시간(성장 가속)만 판다 | `SkillGachaCurve` 머리 주석, `SkillSlotTests.NewSkills_ShareExactlyOneRate` | 신규 7종의 초당 기여(BaseRate)는 전부 **0.180** (ExpansionRate 동률) |
| **밴드가 보는 것은 풀 크기가 아니라 자리 수** - 기준 구성은 `gachaOwned=0` 세계 | `SkillCatalog.ReferenceLoadout`, `SkillCurve.BaseSlots` | 신규 7종을 전부 **GachaGated**로 두면 밴드·시뮬레이션·보스 게이트가 한 비트도 안 움직인다 |
| **사다리는 하나** - 확률·천장·가격·일일 무료는 `GachaCurve` 한 곳 | `SkillGachaTests.Ladder_IsTheSameLadder` | 확률표·가격은 재사용, 새로 정의하는 것은 결과(Outcome) 층과 천장 1종뿐 |

추가 상속: 스킬 XP는 상한(`SkillCurve.CeilingRatio = 3.2`)을 절대 넘기지 못한다.
중복 보상이 무엇이 되든 **도달점은 진행으로 도달하는 곳과 같아야** 한다.

## 1. 데이터 구조 - 계열(Family)과 등급(Grade)의 분리

### 1.1 두 축을 섞지 않는다

현재 코드에 이미 두 층이 있다:

- `GachaCurve.Grade` (★1~★5) = **뽑기 드라마의 층**. 색과 연출을 정한다.
- `SkillGachaCurve.Outcome` = **보상의 층**. 지갑에 뭐가 들어오는지 정한다.

여기에 셋째 축을 추가한다:

```csharp
// SkillCatalog.cs (Progression) - 구현 단계 1
public enum SkillFamily
{
    SwordForm,   // 검식 - 빠르고 안정적인 검술        (UI 병기: "일반")
    BloodForm,   // 혈식 - 피와 요괴의 힘, 변칙 기술    (UI 병기: "상급")
    OniSecret    // 귀오의 - 흐름을 바꾸는 필살기       (UI 병기: "각성")
}

public struct SkillSpec
{
    // ... 기존 필드 유지 ...
    public SkillFamily Family;   // 명시적 데이터. 이름·ID 문자열로 추측 금지
}
```

**Family는 전투 역할의 계열**이고, **Grade는 뽑기 희귀도**다. 별개 축이므로:

- "혈식이니까 ★2" 같은 매핑은 만들지 않는다.
- 뽑기 결과 화면의 별 등급은 지금처럼 Outcome이 정하고,
  스킬 자체의 계열 표시는 Family가 정한다.
- UI에서 "일반·검식"처럼 병기하는 것은 **표시 조합**일 뿐, 데이터는 Family 하나다.

### 1.2 계열별 UI 색 (기존 팔레트 안에서)

| 계열 | 색 방향 | 후보 (기존 사용 색 재활용) |
|---|---|---|
| 검식 | 청백/강철 | 연참 SlashRgba `#A8D8FF` 계열 |
| 혈식 | 짙은 적 | 혈륜 SlashRgba `#C8304C` 계열 |
| 귀오의 | 금 | `UiSkin.Gold` (완성의 색 - 기존 의미와 일치) |

신규 색 정의 없이 카탈로그의 SlashRgba·UiSkin에서 끌어온다.

**설계 근거**:

- **역할 커버리지**: 요구된 10개 역할이 15종 안에 전부 있다 -
  빠른 연속(연참·혈륜), 단일 보스(심격·혈폭), 전방 관통(일섬·낙혈·혈조),
  화면 광역(혈파동·귀참), 다단(연참·혈륜·귀신난무), 지속 피해(검진),
  끌어모음(나락인력), 처형(참수), 전방위(회월참), 각성 필살기(귀참·귀왕강림).
- **쿨타임 스펙트럼**: 신규 7종(4·5·7·12·14·16·19s)이 기존 8종
  (2.5·3·4.5·5.5·6·8·9.5·11s)의 사이와 위를 메운다. 계열 정체성 =
  검식은 짧고 잦게(4~7s), 귀오의는 길고 무겁게(12~19s).
- **귀왕강림(×3.42)이 귀참(×3.52)을 안 넘는 이유**: 귀참은 진행 확정
  스킬이자 게임의 이름이다. 뽑기 스킬이 그 위에 서면 "뽑기가 파워를
  판다"의 체감 버전이 된다. 최장 쿨(19s)로 **한 방의 무게**는 가장
  무겁게 체감되지만 rate는 0.180이다.
- **참수의 처형 규칙은 잡몹 전용**: "체력 30% 이하 잡몹 즉살"은 연출이
  화려하지만, 보스에게는 **총량 동일 규칙**(SkillShape 머리 주석 - 보스는
  단일 대상이라 어느 거동이든 총량이 같다)을 그대로 적용해 배율만 들어간다.
  잡몹 처치 가속은 SpawnPacing 하한(0.4초)이 이미 캡을 치므로 파밍
  밴드도 안전하다 - 코드가 이미 방어해 둔 자리다.
- **나락인력**: 위치만 옮긴다. 데미지는 배율 규칙 그대로라 밴드 무변.
  자동전투에서의 실익은 연출과 잡몹 정리 리듬이지 DPS가 아니라고
  문서에 명시한다(과대 포장 금지).

## 3. 스킬 뽑기 설계

### 3.1 해금 - 상점과 스킬 뽑기를 st14로

현재 `GachaCurve.UnlockStage = 41`이 **상점 탭·요도 배너·스킬 배너·
혈폭/혈조 골드 앵커**를 한꺼번에 잠근다. 설계:

```
ShopCurve.UnlockStage      = 14   // 신설 - 상점 탭 + 스킬 뽑기 배너
GachaCurve.UnlockStage     = 41   // 유지 - 요도 배너 (st41 파워 곡선과 얽혀 있음)
```

- 상점 탭(`LockedTab`)과 스킬 배너는 새 상수를 본다.
- 요도 배너는 st41 그대로 - 요도는 파워 축이라 가속 구간 앵커를 못 옮긴다.
- 신규 스킬들의 `UnlockStage`(골드 비용 기준점)는 **st14**로 적는다.
  `BaseCost = BaseRate × 150 × GoldMultiplier(14)`가 자동으로 그 시점
  수입 규모에 맞는 값을 낸다 (기존 `Skills_HaveTheSameGoldEfficiencyAtUnlock`
  테스트가 그대로 지켜준다).
- **코리더 비트 검증**: st12 혈파동 → **st14 상점+무료 10연** → st15 일섬
  → st18 낙혈 → st21 귀참 → st27 혈륜. 두 칸 간격이 유지되고 사건의
  종류(해금/선택/상점)가 갈려 겹쳐 읽히지 않는다.

### 3.2 온보딩 흐름 (st14)

```
st14 보스 클리어
 └─ 상점 탭 해금 (하단 탭 빨간 점)
     └─ 스킬 뽑기 배너 상단에 "무료 10연" 버튼 (1회성)
         └─ 첫 무료 10연: ★4(해금) 1회 확정 보정
             └─ UnlockOrder[0] = 혈조  →  상급·혈식 1개 확정 획득
                 └─ 슬롯에 끼우는 가이드(기존 가이드 퀘스트 카드가 안내)
```

- 첫 무료 10연의 확정은 **10번째 뽑기에서 ★4 미출현 시 강제 승격**
  (기존 천장 코드와 같은 구조, 카운터만 10). 첫 확정의 해금 대상이
  UnlockOrder 선두의 혈조이므로 "첫 10연 = 혈식 1개 이상"이 구조로 보장된다.
- 혈조(쿨 2.5s)를 선두에 둔 이유: 해금 즉시 전투 리듬이 눈에 띄게
  빨라진다 - 첫 뽑기의 체감으로 가장 크다.

### 3.4 확률표 (기존 `GachaCurve.Chances` 재사용) + 결과 재정의

등급 확률 (표 기준, 공개용):

| 등급 | 확률 | 결과 (재설계) |
|---|---:|---|
| ★1 일반 | 71.6% | 스킬 XP 6 |
| ★2 고급 | 17.5% + 5.0% | 스킬 XP 20 / 70(잭팟) |
| ★3 희귀 | 3.0% | 스킬 XP 240 |
| ★4 영웅 | 2.1% | **스킬 해금** (검식·혈식 풀) → 소진 시 XP 240으로 미끄러짐 |
| ★5 전설 | 0.8% | **귀오의 해금** (귀오의 풀) → 소진 시 개안(즉시 상한) → XP |

- 변경점은 ★5 하나다: 현재 "개안(즉시 상한)" → **"미보유 귀오의 해금,
  전부 보유 시 개안"**. 기존 `SlideFor` 사다리(★5→★4→★3)에 자연스럽게
  얹힌다.
- 천장 보정 산식은 기존 닫힌 식(`PityShare`, `Suppressed`) 그대로 성립
  (확률표가 동일하므로 재유도 불필요 - "사다리는 하나" 계약).
- **UnlockOrder 확장** (★4 대상, 9종 뽑기 스킬 중 검식·혈식):

```
혈조 → 심격 → 혈폭 → 회월참 → 검진        (★4 사다리, 5종)
귀신난무 → 나락인력 → 참수 → 귀왕강림      (★5 사다리, 4종)
```

  고정 순서인 이유는 기존 코드 주석 그대로다 - 화면이 "다음에 무엇이
  나오는가"를 말할 수 있고, 플레이어 간 세계가 갈리지 않는다.

### 3.5 각성 천장 (신설)

- **누적 100회마다 ★5 1회 보장** (별도 카운터, ★4 소프트 천장과 독립).
- 근거: ★5 표 확률 0.8% → 기대 125회. 100회 천장이면 "운이 나빠도
  석 달 안에 귀오의 하나"가 산수로 보장된다(4.3절).
- ★4 천장(30회)이 ★5를 훔치지 않는 기존 규칙(`EffectiveAwakenChance` =
  표와 동일)도 유지 - 각성 천장은 그 위에 얹는 하드 보장이다.
- 화면에는 두 게이지를 다 적는다: "확정까지 n회" (★4) / "각성 확정까지 n회" (★5).

### 3.6 중복 보상 - 스킬 XP 재사용 (신규 재화 없음)

- 이미 보유한 스킬이 해금 자리에 나오면 기존 `SlideFor` 규칙대로
  **한 칸 아래(XP)로 미끄러진다**. "중복 카드"라는 별도 재화를 만들지
  않는 이유는 코드가 이미 적어 둔 판단 그대로다 - 재화가 하나 늘면
  faucet·화면·세이브·밴드 모델이 함께 늘고, 스킬 XP가 이미 그 일을 한다.
- UI 표기만 "스킬 조각"으로 감싼다: XP 게이지(기존 "12 / 16" 표시)가
  곧 조각 진행도다. 데이터는 기존 `skillXp` 하나.
- 진행 확정 스킬(연참~혈륜, 귀참)은 뽑기 풀에 없으므로 중복 문제 자체가
  없다.

### 3.7 귀참 확정 지급 (요구 9)

현재 구조 그대로 충족된다: 귀참은 Lv.20/st21 **진행 해금**이라 과금·뽑기와
무관하게 모든 플레이어가 각성 스킬 1개를 확정 보유한다. 설계 변경 없음 -
문서에 계약으로 명시만 한다.

(온보딩 무료 10연은 별도 +10회)

### 4.3 획득 시간 전망

| 이정표 | 산식 | 전망 |
|---|---|---|
| 첫 혈식 (혈조) | st14 무료 10연 확정 | **첫날** (st14 도달 = 플레이 1일차) |
| ★4 1개당 기대 뽑기 | (1-0.971³⁰)/0.029 ≈ 20.2회 | 천장 포함 실효 4.95%/회 |
| 검식·혈식 5종 (★4 사다리) | 5 × 20.2 ≈ 101회 | 무과금 **~7주** |
| 첫 추가 귀오의 | ★5 0.8%/회, 천장 100회 | 기대 ~60회(30일)에 48%, **늦어도 50일(천장)** |
| 귀오의 4종 (★5 사다리) | 4 × min(125, 100) = ~400회 | 무과금 **~6-7개월** (장기 목표) |
| 오의 1개 상한 (XP 682) | 682 / 18.1 XP ≈ 38회 | 천장 한 바퀴+α - 기존 리듬 유지 |

**막힘 없음 검증**: 전투에 필요한 것(슬롯 4 + 진행 스킬 6종 + 귀참)은
전부 진행으로 열린다. 뽑기 스킬 9종은 전부 rate 0.180 동률이라 **없어도
DPS가 밴드 밑으로 떨어지지 않는다** - 뽑기가 파는 것은 선택지(폭)이지
진행 필수 파워가 아니다. 이것이 "무과금 진행 불가 구간 없음"의 구조적
증명이고, 기존 `TheSlotBudget_DoesNotDependOnWhichSkillIsEquipped`
테스트가 15종으로 늘어난 뒤에도 같은 것을 지킨다.

**과금이 사는 것**: 시간(XP 가속·수집 완성)과 폭(역할 선택지). 파워 아님.

## 7. 재사용 vs 신규 구현

### 7.1 그대로 재사용 (수정 없음 또는 데이터 추가만)

- `GachaCurve` 확률표·가격·소프트 천장·닫힌 식 전부
- `SkillGachaCurve`의 XP 사다리·SlideFor·UnlockOrder 구조 (배열만 확장)
- `SkillSystem` 장착·레벨·XP·자동 시전 (신규 스킬은 카탈로그 행 추가)
- `SkillShape.MultiHit/Pierce/Screen` - 신규 7종 중 3종(심격·귀왕강림·혈폭류)이 기존 거동만으로 성립
- 세이브의 id 병렬 배열 구조
- 쿨타임 HUD(SkillCooldownOverlay) - 슬롯 기반이라 스킬 수와 무관
- 상점 배너 골격·확률표 팝업·등급 색
- VFX: wave/whip/crescent/pozac 3종 + Slash 팩 재염색(SlashRgba는 데이터)

### 7.2 신규 구현 필요

## 9. 리스크 요약

1. **세이브 v20** - 필드 2개 추가뿐이지만 천장 크레딧 소급(6절) 누락 시
   기존 뽑기 유저가 손해를 본다. 마이그레이션 테스트 필수.
2. **처형·틱 거동** - "보스 총량 불변" 계약을 깨기 가장 쉬운 자리.
   구현 전에 SkillShapeTests에 계약 테스트부터 추가할 것.
3. **상점 st14** - 보석 faucet 대비 소비처가 하나 앞당겨진다. 코리더의
   보석 업적(st5 20젬, st10 40젬)만으로 첫 주 뽑기 리듬이 성립하는지
   시뮬 재확인 필요.
4. **폰트** - "검식/혈식" 표기가 문자셋 재굽기 없이는 □로 뜬다.
   1단계에서 가장 먼저 처리.
5. **★5 재정의** - 기존에 ★5 개안을 기대하던 유저의 상품이 바뀐다.
   귀오의 소진 후 개안으로 미끄러지므로 장기적으로 손해는 없지만,
   공개 확률표 문구를 정확히 갱신해야 한다.
