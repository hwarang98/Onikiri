# 승급·전직 재설계 — 2.1단계 (심층 수렴 폐쇄) 보고서

B-1 승인에 따라 **문5·6에만 작용하는 심층 수렴 보정**을 넣었다. 3단계(전투·씬·UI·
Save v21·Android)로 넘어가지 않았다.

**EditMode 725개 중 723 통과 / 2 실패.**

```
복구됨   DeepZone_MarginConverges          +50.4% -> +25.98% / +27.68%  (기준 <35%)
복구됨   Affinity_IsNotADeadButton         3.61% -> 4.14%              (기준 >4%)
복구됨   SpiritSummon_IsNotADeadButton     2.486% -> 2.69%             (기준 >2.5%)
미복구   MasteryNeutralized_ReproducesTheStep42World
미복구   YodoPowerNeutralized_ReproducesTheStep44World
```

미복구 둘은 **어떤 심층 지수로도 복구되지 않는다.** 산수로 증명했고 §4가 그 자리다.
기준값을 낮추거나 넓히지 않았고 `BossHealthRampDeep` · `YodoPowerMarginExponent` ·
`AffinityTierStep` · 영체 계수도 손대지 않았다.

## 1. 새 보정 — 이름도 역할도 전역 보정과 섞지 않았다

```csharp
// StageCurve
public const double DeepPromotionConvergenceExponent = 0.55d;
public static double DeepPromotionCompensation(int stage);

// PromotionTrialCatalog
public const int FirstDeepGate = 5;
public static bool IsDeepGate(int gateNumber);

// EvolutionCurve
public static double AttackMultiplierBetween(int fromTier, int toTier);
```

| | 지워진 `EvolutionMarginExponent` | 새 `DeepPromotionConvergenceExponent` |
|---|---|---|
| 목적 | 무과금(1티어)과 과금(6티어)의 **티어 격차** 보정 | st100·st150의 **영구적 여유 계단**이 심층 수렴과 다른 성장축을 죽이는 것 방지 |
| 걸리는 문 | 여섯 전부 | **다섯·여섯만** |
| 전제 | 플레이어마다 티어가 다르다 | 전원이 같은 티어를 같은 자리에서 받는데도 필요하다 |
| 상태 | **삭제됨** (승인 A-1) | 신규 (승인 B-1) |

되살린 것이 아니라 다른 것이다. 두 파일의 주석이 그 구분을 명시하고,
`PromotionDomainTests.EveryGate_MovesRealPowerByTheApprovedAmount`가 문1~4를
1e-12로 고정해 두 목적이 섞이면 즉시 실패하게 만든다.

`Math.Pow`를 지나는 것은 티어 5 이상에서뿐이다 — 티어 4 이하는 이른 반환으로
정확히 `1.0`이라 조율 코리더와 가속 구간이 **구조적으로** 불변이다.

### 단일 출처

`PromotionTrialCatalog.TierAtFrontier` 하나만 쓴다. `>=` 비교를 어느 파일에도
복제하지 않았다 — `StageCurve` · `StageSimulation` · `PromotionBandModel` ·
`SaveData`가 전부 그 함수를 지난다.

## 2. 경계 실측 — 클리어해야 걸린다

| 스테이지 | 티어 | `DeepPromotionCompensation` |
|---:|---:|---:|
| st1 ~ st100 | 0~4 | **1.000000** (비트 단위 1.0) |
| st101 | 5 | 1.079901 |
| st150 | 5 | 1.079901 |
| st151 | 6 | 1.193805 |

`st100`에 **도착**한 상태는 문5를 깬 상태가 아니므로 보정이 없다. 등호를 썼다면
하한 플레이어가 문5를 더 무거운 보스로 만났을 것이다 — 진행이 막히는 경로다.

`PromotionDomainTests.DeepCompensation_AppliesOnlyAfterTheGateIsCleared`가
st1~100 전 구간을 비트로, 네 경계를 값으로, 단조성을 st400까지 검사한다.

`DeepGateBoundary_StartsWhereTheDriftWindowDoes`는 `FirstDeepGate = 5`가 임의
상수가 아니라는 것을 잰다 — 드리프트 창이 st100 -> st200이고, 그 창 **안에서**
티어가 오르는 문이 정확히 다섯째·여섯째다. 넷째(st70)는 창이 열리기 전에 끝나
st100과 st200 양쪽에 똑같이 들어가 비에서 상쇄된다.

전부 통과하므로 승급 체감을 최대한 보존하는 쪽을 골랐다 — 문5가 6.49%로 마일스톤
바닥(5%)에서 가장 멀고, 문6도 8.55%로 가장 크다.

여유도 확인했다:

```
드리프트     0.2768  (기준 0.35, 여유 26%)
Affinity     4.14%   (기준 4.00%, 여유 0.14%p)   <- 가장 얇다
Spirit 지금  2.69%   (기준 2.50%, 여유 0.19%p)
문5 체감     6.49%   (기준 5.00%, 여유 1.49%p)
```

Affinity가 가장 얇다. 다만 지수를 올려도 4.14 -> 4.24%로 0.1%p밖에 안 늘므로
(위 표), 그 축의 여유는 이 손잡이로 살 수 있는 것이 아니다 — 필요해지면
`AffinityTierStep` 쪽이 맞는 자리이고 이번 단계의 범위 밖이다.

**e5/e6 분리는 검토하지 않았다.** 공통 지수가 조건을 만족했으므로 상수를 둘로
나눌 근거가 없다.

## 4. 미복구 둘 — 산수로 불가능하다

두 검사 다 **과거 세계의 재현 스냅샷**이고, 살아 있는 계약(드리프트·죽은 버튼
둘)은 전부 복구됐다는 것이 이 절의 요점이다.

### 4.1 `MasteryNeutralized_ReproducesTheStep42World`

두 군데가 걸린다.

**(a) 앵커 st40 · st50 — 어떤 지수로도 안 움직인다**

```
실측      st10 = 1.5222  st30 = 1.4437  st40 = 1.6664  st50 = 1.9525
굳힌 값   st10 = 1.5222  st30 = 1.4438  st40 = 1.3771  st50 = 2.3413
심층 몫   st40 = 1.0     st50 = 1.0     <- 보정이 지나가지 않는 자리다
```

st40·st50은 **가속 구간**이고 B-1은 그 구간을 건드리지 않기로 한 변경이다.
`DeepPromotionCompensation`이 거기서 정확히 1이므로 지수를 아무리 올려도 두 값은
1.6664 / 1.9525에 그대로 앉아 있다.

두 값이 움직인 원인은 2단계의 승인 사항 자체다 — 전역 보정 삭제(A-1)와 게이트
무료 티어가 st31~50의 세계를 **의도적으로** 다시 만들었다. 코리더(st10·st30)가
비트로 불변인 것이 그 변경이 설계대로 갔다는 증거다.

**(b) 심층 천장 13.6 — 필요한 지수가 체감 바닥과 충돌한다**

```
최소 필요 e = 0.8812  (binding st191)  ->  그때 문5 체감 1.67%
문5 체감 5% 를 지키는 e 상한 = 0.6509
```

**(c) 재현할 세계가 사라졌다.** 이 검사가 굳힌 것은 "42단계의 st40 여유"인데,
승인된 재설계가 그 스테이지의 세계를 바꿨다. 검사 주석 자체가 이 값들이 43단계
미세화와 E-3 수정 때 **두 번 재기준됐다**고 적고 있다 — 세계를 의도적으로 바꿀
때 앵커를 다시 굽는 것이 이 파일의 절차다.

**이번 단계에서는 굽지 않았다.** "기준값을 새 결과에 맞춰 낮추거나 넓히지
않는다"는 지시가 우선이고, 재기준은 승인 사항이라고 판단했다.

### 4.2 `YodoPowerNeutralized_ReproducesTheStep44World`

```
실측 (e=0.55)  st121 천장 12.43  (기준 12.342)
최소 필요 e = 0.7259  (binding st165)  ->  그때 문5 체감 3.91%
문5 체감 5% 를 지키는 e 상한 = 0.6509
```

**0.0750만큼 모자란다.** 심층 지수를 0.7259까지 올리면 이 검사는 통과하지만 문5의
승급 체감이 3.91%로 떨어져 마일스톤 계약(>= 5%)이 대신 깨진다 — 두 계약이 지수
하나를 반대 방향으로 당기고, 그 사이에 답이 없다.

이 검사도 **44단계 세계의 재현 스냅샷**이다(천장 12.10 · 8.72 · 6.91). 살아 있는
심층 밴드는 `DeepZone_MarginConverges`가 지키고 그쪽은 복구됐다.

### 4.3 선택지

| # | 선택지 | 대가 |
|---|---|---|
| **C-1** | 두 재현 앵커를 **다시 굽는다** (43단계·E-3 때와 같은 절차) | 42/44단계 세계와의 비교가 그만큼 끊긴다. 코리더 앵커(st10·st30)는 비트로 남으므로 조율 구간의 재현은 유지된다 |
| **C-2** | 심층 지수를 0.7259로 올린다 | 문5 체감 3.91% — 마일스톤 계약이 대신 깨진다. `MasteryNeutralized`는 여전히 안 풀린다(0.8812 필요) |
| **C-3** | 문5·6의 티어 스텝(1.15 / 1.20)을 키운다 | 체감 여유가 늘어 더 높은 지수를 쓸 수 있다. 다만 티어 배수 총합(x2.0946)이 움직여 밴드 전체를 다시 유도해야 한다 |
| **C-4** | 두 검사를 **재현 검사에서 부등호 검사로** 바꾼다 | `YodoPowerNeutralized`의 심층 상한은 이미 그 성격이다(46·47단계에 8.5 -> 10.6 -> 13.6으로 두 번 올렸다). 같은 근거로 한 번 더 올리는 것이 일관되지만, 그것이 "기준값을 넓히는 것"이라 지시와 충돌한다 |

C-1이 가장 좁고 이 파일들의 기존 절차와도 맞아 보인다. 승인 없이 시작하지 않았다.

## 5. 문별 실질 상승률

```
문1  10.000000%   문2  10.000000%   문3  12.000000%   문4  12.000000%   <- 1e-12 고정
문5   6.49%       문6   8.55%                                          <- >= 5%
```

`PromotionDomainTests.EveryGate_MovesRealPowerByTheApprovedAmount`가 다섯을 잰다:

- 문1~4를 승인값에 **1e-12**로 고정 — 심층 보정이 번지면 `1.10^(1-0.55) = 4.4%`가
  되어 즉시 실패한다
- 문5·6이 마일스톤 바닥(5%) 위
- **모든 문에서 실질 상승 > 0** — 티어가 오를수록 전투력이 줄어드는 구간 없음
- 모형(`PromotionBandModel.FeltGainAtGate`)과 곡선이 같은 답

실질 상승을 `EvolutionCatalog`의 스텝에서 읽지 않고 **보정을 지나는 경로**로
잰다(`RealGainAtGate` — 문 앞과 문 뒤의 `배수 / 보정`을 프로덕션 함수로 각각
계산). 스텝만 읽으면 보정이 잘못 걸려도 통과하는 검사가 된다.

### 6.1 M 표 — **육문 하나만 움직였다**

45초 하한 앵커 규칙에서 다시 유도했다. 값을 직접 맞추지 않았다.

| 2 | 40 | 1.9528 | **1.9528** | 보정 밖 |
| 3 | 50 | 2.1813 | **2.1813** | 보정 밖 |

## 7. k 후보 — 셋 다 수학적으로 통과한다

`SoftCapExponent = 0.45`는 **후보 확정값으로 유지**했다. 최종 고정하지 않았다.

| k | 곡선 추종 최속 | 중간 범위 | 하한 | 25초 바닥 | 밴드 [35,55] |
|---:|---:|---|---:|---|---|
| 0.35 | 36.7s | 40.6~44.1 | 45.0s | ○ | ○ |
| **0.45** | **34.7s** | **39.5~43.9** | **45.0s** | **○** | **○** |

## 8. 통합 시간 장부 (재산출)

## 10. 3단계 시작 가능 여부

**조건부 가능.** 살아 있는 밸런스 계약은 전부 닫혔다.

```
닫힘   심층 수렴 · 요도 상성 · 요도 영체 · 문1~4 체감 · 문5·6 체감 ·
       도달층 · 과금 리드 · 45초 앵커 · 폭 계약 · 종료 보장 · 경계
열림   C-1~C-4 (42·44단계 재현 스냅샷 둘)
```

열려 있는 둘은 **과거 세계와의 비교**이지 현재 밸런스의 계약이 아니다. 3단계
전투·연결 작업은 이 둘과 독립이므로 지금 시작해도 보스 체력 곡선을 다시 만질
일이 생기지 않는다 — 2단계 보고서가 3단계를 막았던 이유(살아 있는 밴드가 열려
있었다)가 해소됐다.

다만 두 검사가 빨간 채로 3단계에 들어가면 그 단계에서 새로 깨진 것과 구분이
안 된다. **C-1~C-4 중 하나를 먼저 정하는 쪽을 권한다** — C-1이면 앵커 재굽기
한 번으로 725/725가 된다.

3단계 연결 목록과 Android 실기 테스트 계획은 2단계 보고서 §9 · §11 그대로다.
