# 29단계 보고 — 스킬 이펙트 원복 (절차적 메시 폐기 → 팩 슬래시 애니)

순수 연출이다. **밸런스·세이브·타격 분배 무관.** 총 데미지와 캐스트 수 불변.

## 0. 방향 정정 — 두 번 다 크기가 원인이었다

27단계: 64px 참격 **한 장**을 3.4배로 키웠다 → 픽셀이 네모가 됐다.
28단계: 그 뭉개짐을 고치려고 같은 크기의 **메시**를 그렸다 → 뭉개짐은 사라졌지만
화면을 덮는 덩어리는 그대로였다.

정정이 맞다. 뭉개짐은 증상이었고 원인은 **"화면을 가로지르는 초대형 참격"이라는
전제** 쪽이었다. 28단계 보고에 "가로 7.4u = 카메라 폭의 92%"라고 자랑스럽게 적어둔
숫자가 사실은 문제의 크기였다.

이번에는 팩으로 돌아오고 크기를 줄인다.

검은 윤곽이 밝은 벚꽃 배경에서 형태를 잡아 주므로 그대로 채택했다.

## [F-1] 귀참 — 전방으로 크게 가르는 한 방

![귀참](../Assets/Screenshots/step29_oni_slash.png)

**크기 (실측).** 절정 프레임(4번)의 잉크가 80×80px. 32 PPU에서 배율 2면

```
80px / 32 * 2 = 5.0u
사무라이 키 3.0u 대비 1.67배      (사양: 1.5~2배)
카메라 폭 8.03u 대비 62%          (화면을 덮지 않는다)
```

**광역 타격은 그림이 아니라 히트박스가 한다.** `DeliverAll`이 살아 있는 요괴 전부를
때리고, 그림은 사무라이 앞을 한 번 가른다. 이펙트가 맞는 것들을 물리적으로 덮을
필요가 없다는 것이 이번 정정의 핵심이고, 덮으려다 화면을 가린 것이 28단계다.

히트스톱 3.0배 / 셰이크 2.8배 / 숫자 2배 / 화면 연출 유지 — 무게는 여기서 난다.

### 두 번 물린 곳

**(1) 피벗을 프레임 중심에 뒀더니 그림이 날아갔다.** 팩 프레임 안에서 그림은 가운데
있지 않다. −90° 회전에서 회전축과 그림 사이 거리만큼 밀려, 참격이 앵커(0.40, 0.97)
대신 화면 오른쪽 끝으로 나가 잘렸다. 배율 2배가 그 어긋남까지 2배로 키운다.

처음 고칠 때는 **열 장의 잉크 합집합** 중심을 썼는데, 합치면 프레임을 거의 다 덮어서
결과가 (65, 69.5)/128 — 프레임 중심과 사실상 같았고 아무것도 고쳐지지 않았다.
합집합은 "어디에 그려졌나"가 아니라 "어디까지 갔나"를 잰다.

**잉크가 가장 많은 프레임 하나**를 대표로 뽑아 그 중심을 열 장이 공유하게 해서 풀었다.
프레임마다 따로 잡으면 팩의 내부 움직임이 상쇄되어 참격이 지나가지 않고 제자리에서
커졌다 작아진다.

```
Slash3_color2: peak frame 4 (2041px ink) spans 27..106 x 33..112 -> pivot (0.523, 0.570)
Slash2_color4: peak frame 2 (1780px ink) spans 20..112 x  4..83  -> pivot (0.520, 0.344)
```

**(2) 앵커는 그림의 자리가 아니라 호의 곡률 중심이다.** 초승달은 굽은 선이라 잉크
경계의 한가운데가 **오목한 안쪽의 빈 곳**이다. 앵커를 0.92에 뒀더니 붉은 호는 2.25에
떴다 — 1.3u 차이가 곧 호의 반지름이다. 앵커를 사무라이 바로 앞(0.8u)으로 당겨
호가 앞으로 부풀게 했다. 칼 쥔 손이 중심이고 궤적이 뻗어 나가는 모양이라 우연히도
이쪽이 실제 베기와 더 닮았다.

각도는 −90°에서 −55°로 눕혔다. −90°면 5.0u가 통째로 세로로 서서 전투 띠(약 3.5u)를
위아래로 넘치고, 모양도 "가로막는 벽"이 된다. −55°면 세로 폭이 4.1u로 줄고 **비스듬히
내려긋는 베기**가 된다.

## [F-2] 일섬 — 돌진 + 팩 슬래시

![일섬](../Assets/Screenshots/step29_flash_slash.png)

절차적 스트릭을 버리고 팩으로 통일했다. Slash2는 열 프레임이 한 방향으로 그어지고
끝에 임팩트가 터지는 모양이라 찌르고 지나가는 돌진과 주기가 같다.

배율 1 = **원본 픽셀 크기**. 일섬은 셋 중 가장 빠른 오의라 크기보다 속도로 읽혀야 한다.
잉크 2.9×2.5u로 사무라이 키 언저리다.

**28단계에서 고친 DASH 잔상은 그대로 유지했다** — 시각 예약 방출, 거리 균등 배치
(0.475 / 0.95 / 1.425u), 알파 0.36 / 0.58 / 0.79. 위 스크린샷 왼쪽의 흰 잔상이 그것이다.

X 앵커 복귀(`lungeBack`), 관통 사거리 4.6 × 세로 2.6 그대로다.

### 첫 판이 어색했다 — 두 가지가 어긋나 있었다

플레이 소감으로 "일섬만 어색하다"가 들어와 다시 쟀다. 원인 둘 다 실측으로 나왔다.

**(1) 참격이 돌진보다 길어서, 돌아온 뒤에도 혼자 재생됐다.**

```
t40  사무라이 x=0.70 (돌진 최대 1.90)   참격 아직 없음
t64  x=0.58 이미 복귀 중                참격 시작 @2.30
t152 x=-1.20 원위치, 정지               참격 5/10 프레임
t240 x=-1.20 계속 서 있음               참격 10/10 프레임
```

34fps에서 열 장이 0.29초인데 돌진은 0.09초에 최대를 찍고 0.26초면 앵커로 돌아온다.
화면에서는 **"베고 돌아왔는데 참격만 3.5u 떨어진 곳에 혼자 남아 있다"**로 보인다.

재생 속도를 60fps(0.167초)로 올리고 복귀를 0.17 → 0.24초로 늘렸다. 고친 뒤:

```
Slash2_color4_00  lunge=1.83     <- 참격 시작, 사무라이 아직 나가 있다
Slash2_color4_09  lunge=0.32     <- 참격 끝, 이제 복귀
```

열 장 전부가 돌진 구간 안에서 끝난다.

**(2) 회전각의 부호가 반대였다.** 팩 원본은 왼쪽 위에서 오른쪽 아래로 −70도쯤 긋는
사선이다. 거기에 −60을 더하면 −130도가 되어 **더 가팔라진다** — 앞으로 찌르는 것이
아니라 내려찍는 모양이고, 스크린샷에서 아래로 꺾인 V자로 보이던 것이 그것이다.
+70을 더해야 0도, 곧 수평 찌르기가 된다.

지금은 사무라이 칼끝에서 시작해 요괴 열을 가로질러 끝에서 임팩트가 터진다.

## [F-3] 연참 — 그대로

![연참](../Assets/Screenshots/step29_chain_intact.png)

씬에 박힌 값을 되읽어 확인했다:

usesSlash=False  slashFrames=0  ghosts=0  lunge=0
hitStop=1.4  shake=1.1  perHitShake=0.55  numberSize=1  flash=False

## 확대 검증 — 여기는 솔직히 보고할 것이 있다

![확대](../Assets/Screenshots/step29_zoom.png)
*위=귀참(배율 2) ×6, 아래=일섬(배율 1) ×6*

- **일섬(배율 1)**: 참격의 계단이 배경 아트와 **정확히 같은 4픽셀**이다. 같은 격자에
  얹혀 있어 구분이 안 된다.
- **귀참(배율 2)**: 계단이 **8픽셀**로 배경의 딱 두 배다. 확대하면 눈에 띈다.

이건 버그가 아니라 배율 2의 정의 그대로다. 사양이 "귀참은 셋 중 가장 크게(~2~2.5배),
캐릭터 키의 1.5~2배"를 요구했고 그 값이 정확히 이 비용을 치른다 — 배율 1로 내리면
격자는 완벽히 맞지만 잉크가 2.5u(캐릭터 키의 0.83배)로 줄어 사양의 크기 요구를 벗어난다.
**둘 다는 안 된다.** 지금은 사양대로 크기를 택했다. 격자 일치가 더 중요하면
`slashScale`을 1로 내리면 된다(빌더 한 줄).

빌드 검사에 배율 상한 2.5를 넣어 두었다 — 넘기면 빌드가 실패한다.

## 공통 마감

- **앵커·반전**: 반전은 23단계 규칙대로 부르는 쪽(요괴의 `FacingDirection`)이 정한다.
  좌우 반전은 세로축 거울이므로 **회전각의 부호도 함께 뒤집는다** — 안 뒤집으면 왼쪽을
  벨 때 참격이 위아래가 바뀐 채 나간다. 전방 오프셋의 부호도 같이 뒤집어 등 뒤에 뜨지
  않게 했다.
- **timeScale=0 동결**: `PackSlash.Update`가 `Time.deltaTime`(스케일 타임)을 쓴다.
  히트스톱이 참격도 함께 얼린다.
- **숫자 focal 유지**: 색(#A8D8FF / #FF4A3A / #FF9500)·크기(1/2/2)·이름 플래시 그대로.
- **풀링**: `ObjectPool<PackSlash>` prewarm 3. 시전 경로에 `Instantiate` 없다.
- **시트 자르기**: 빌더가 640×256을 5열×2행 열 장으로 자른다. 팩은 Single로 임포트되어
  있어서 자르지 않으면 정적인 한 장이 되고, 그것이 27단계 실수의 출발점이다.
  빌드 검사에 "참격 프레임이 1장이면 실패"를 넣어 그 경로를 막았다.
