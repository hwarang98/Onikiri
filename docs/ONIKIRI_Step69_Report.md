## 0. 한 줄 요약

상점의 두 뽑기를 **배너 행 하나씩**(큰 아이콘 · 제목 줄 · 1회 / 10회 버튼 · 소환 레벨 바)으로 접어 9:16에서 **스크롤 없이 두 배너가 같이 서게** 했다. 결과는 **전체 화면 판 + 5열 정사각 타일**(등급 색 테두리 · ★4 보라 / ★5 금 발광 · 차례로 열림 · 확인 · 재뽑기의 첫 탭은 전부 열기 — **판(딤) 탭은 70단계에 구현**, §3 정정)이고, 판 위에서 바로 10회를 다시 뽑을 수 있다. 레벨업은 판이 닫힌 뒤 배너 바에서 **채움 → 번쩍 → "소환 Lv.n" 펀치 → 0부터 다시 채움**으로 한 번씩 순서대로 재생된다. 확률표는 제목 줄의 "확률" 버튼 뒤 팝업으로 옮겼고, 그 표는 **그 배너의 지금 소환 레벨 표**다.

## 4. 레벨업 연출 (결정 4)

    판이 떠 있는 동안 → 큐에 쌓기만 한다 (결과 판에서 재뽑기로 오른 레벨도)
    판이 닫히면, 배너마다 레벨업 하나씩 차례로:
      채움 0.25초 (지금 → 끝)   라벨 = 옛 레벨,  숫자 = 옛 레벨의 꽉 찬 값 (예: 35 / 35)
      번쩍 0.15초 (흰색 → 바 색)
      펀치 0.22초 ("소환 Lv.n" 1.45배 → 1배)   바 0, 숫자 = 0 / 다음 요구
      다시 채움 0.25초 (0 → 실제 비율, 큐가 남았으면 0에서 다음 바퀴)   숫자 = 실제 값

캡처하다 고친 것 둘:

- 연출하는 동안 바 숫자가 이미 새 레벨 값(37 / 41)이었고 라벨만 옛 레벨이었다 → 단계마다 숫자를 맞췄다(`SetFull`)
- 펀치 1.45배에서 라벨("소환 Lv.7" 149px → 216px)이 제 칸(200px)을 넘어 **바 뒤로 들어가 "Lv.7"이 잘렸다** → 배율을 칸 폭 안으로 묶고(`PunchScale`, 이 라벨은 1.34배), 커지는 동안은 바 위에 그린다

둘 다 PlayMode 검사로 묶었다(§6.3).

## 6. 테스트

### 6.1 EditMode — 1069 / 1069 (MCP, 304초, 마지막 수정 반영, 한 번에)

    1073 (마무리 전 기준) − 5 (로직 SHA-256 고정, 조건 2로 삭제) + 1 (확률 팝업 아랫줄 · 칸 글자) = 1069

**멈춤 기록** — 마무리 전, 글꼴 수정 뒤의 전량 실행이 **두 번** 도중에 멈췄다(테스트 씬 "Untitled"에서 CPU 정지 · 응답 없음, 68단계와 같은 모양). 둘 다 사용자가 에디터를 재시작했다. 재시작 뒤 지시대로 픽스처 묶음 1(15개 클래스)을 나눠 돌렸고 **225 / 225**(40초)였다. 그 뒤 마무리 수정을 넣고 전량을 다시 돌렸을 때는 **멈추지 않고 한 번에** 끝났다(아래 수치). 원인은 확인하지 못했다 — 두 번 모두 MCP 웹소켓 끊김이 같이 찍혀 있다.

### 6.2 PlayMode — 71 / 71 (MCP, 108초, 마지막 수정 반영)

69 + 확률 팝업 1 + 인트로 구독자 1. 그리고 **조건 3의 실제 경로**도 손으로 확인했다: PlayMode 전량 직후 같은 에디터에서 Play → 인트로 건너뛰기 → 콘솔 오류 **0건**.
